# 你有酒吗 — AI 多风格短篇故事 App 产品与技术方案

> "你有酒吗？我有故事。"
> 多风格短篇小说生成（1-1.5 万字），支持用户输入开头、大纲、主要剧情，任意组合起步
> 日期：2026-08-31

---

## 一、产品定位

### 产品名

**你有酒吗** — "你有酒吗？我有故事。" 最古老的 storytelling 邀请，变成一款 App。

### 目标

打造一个**小说写作工程化系统**：

- **聚焦短篇**（1-1.5 万字），单线紧凑结构，不需要长篇的复杂上下文管理
- **多风格支持**：内置多种风格模板（知乎盐选、起点玄幻、晋江古言、豆瓣文艺、悬疑推理……），并支持用户上传样本文本自动生成**自定义风格**
- **灵活起步**：用户可以从一个题材开始，也可以直接输入**开头、大纲、主要剧情**，AI 围绕用户的素材续写、补全、展开
- **多模型可切换**（Claude / GPT / DeepSeek），不绑定单一模型

### 一句话定位

> **你有酒吗** — 给一个题材、一段开头、一份大纲，或几个关键剧情，还你一篇情绪饱满、让人停不下来的故事。

---

## 二、核心能力

### 2.1 多风格写作系统

风格不是"换个 prompt 词"，而是一套完整的写作约束包。每个风格模板包含：

| 维度 | 说明 |
|------|------|
| 叙述视角 | 第一人称 / 第三人称限知 / 全知视角 |
| 语言节奏 | 句长、段落长度、对话占比 |
| 情绪线 | 全文情绪走向（如：虐 → 爽 → 甜） |
| 结构规则 | 篇幅分配、反转密度、钩子密度 |
| 文风规则 | 用词偏好、修辞风格、禁忌表达 |
| 风格示例 | 2-3 段范文，作为 few-shot 注入 |

#### 内置风格模板（首期）

| 风格 | 视角 | 情绪线 | 特征 |
|------|------|--------|------|
| 知乎盐选·甜宠逆袭 | 第一人称 | 虐 → 爽 → 甜 | 导语钩子开篇、短句短段、高频反转、结尾爽+甜双满足 |
| 知乎盐选·悬疑反转 | 第一人称 | 紧张 → 悬疑 → 震撼 | 开篇"不对劲"细节、每千字一个线索、至少 2 次重大反转 |
| 起点玄幻·热血升级 | 第三人称 | 压抑 → 爆发 → 昂扬 | 金手指设定、打脸节奏、境界体系、章末钩子 |
| 晋江古言·情深不寿 | 第一/三人称 | 甜虐交替 | 古典措辞、细腻心理、误会与和解、余韵收尾 |
| 豆瓣文艺·都市情感 | 第一人称 | 平淡 → 波澜 → 释然 | 克制笔法、细节流、生活质感、开放式结尾 |

#### 自定义风格（用户自己的文风）

```
用户粘贴 1-3 段样本文本（自己的作品或喜欢的作者）
    ↓ [风格分析 Prompt]
AI 输出：视角/句长分布/段落习惯/对话密度/修辞偏好/情绪表达方式/禁忌项
    ↓
生成该风格的 StyleTemplate，可保存、命名、复用
```

### 2.2 灵活输入：四种起步模式（可任意组合）

用户不必从零开始，手上有什么素材就用什么素材起步：

| 模式 | 用户输入 | AI 行为 |
|------|----------|---------|
| **题材模式** | 关键词 / 一句话题材 | 全自动生成：构思 → 角色 → 大纲 → 正文 |
| **开头模式** | 一段写好的开头（50-500 字） | 分析开头的视角/语气/已埋伏笔 → 反推梗概与大纲 → 从用户开头无缝续写 |
| **大纲模式** | 自由格式大纲 / 梗概 | 解析为结构化节拍表（保留用户原意）→ 生成角色 → 逐节拍展开正文 |
| **剧情模式** | 若干关键剧情点（如"她发现丈夫的秘密""雨夜摊牌""反转：秘密其实是……"） | 点连成线：在剧情点之间补写过渡、铺垫与冲突 → 生成完整大纲 → 展开正文 |

**模式可混合**：例如「开头 + 主要剧情」「大纲 + 指定风格」「题材 + 自定义文风」。

核心原则：**用户提供的素材是"锚点"，AI 必须保留并围绕其展开，不得改写用户给定的开头和关键剧情**。

## 三、技术方案

### 3.1 技术选型

| 层级 | 技术 | 理由 |
|------|------|------|
| 前端 | Next.js 15 + TypeScript + Tailwind + shadcn/ui | SSR 灵活，组件生态好 |
| 编辑器 | Tiptap (ProseMirror) | 富文本编辑，支持内联 AI 操作 |
| 状态管理 | Zustand | 轻量，适合文档类应用 |
| 后端 | Next.js API Routes + tRPC | 前后端同仓，类型安全 |
| 数据库 | PostgreSQL + Drizzle ORM | 结构化数据，类型推导好 |
| LLM 调用 | Vercel AI SDK | 统一流式接口，内置多模型支持 |
| 部署 | Vercel / Docker | 初期快速上线，后期可自部署 |

### 3.3 核心数据模型

```typescript
// 故事项目
interface Story {
  id: string;
  title: string;
  genre: 'romance' | 'suspense' | 'revenge' | 'sweet' | 'horror' | 'fantasy' | 'literary' | 'xuanhuan';
  styleId: string;                 // 风格模板 ID（内置或自定义）
  targetWordCount: number;         // 目标字数 (10000-15000)

  // —— 用户自由输入（全部可选，任意组合）——
  userOpening?: string;            // 用户输入的开头（作为锚点，正文原样保留）
  userOutline?: string;            // 用户输入的大纲/梗概（自由格式）
  keyPlots?: KeyPlot[];            // 用户输入的主要剧情点

  // —— AI 生成 / 用户确认后落定 ——
  logline: string;                 // 一句话梗概
  synopsis: string;                // 详细梗概（500-800字）
  hook: string;                    // 导语/开篇钩子（若用户已提供开头则为空）
  openingAnalysis?: OpeningAnalysis; // 用户开头的分析结果

  modelProvider: string;           // 当前使用的模型
  modelId: string;
  status: 'draft' | 'in_progress' | 'completed';
}

// 用户提供的主要剧情点
interface KeyPlot {
  id: string;
  order: number;
  content: string;                 // 剧情点描述
  locked: boolean;                 // true = 必须原样保留该情节，AI 只能补充其前后过渡
}

// 用户开头的分析结果（开头模式产物）
interface OpeningAnalysis {
  pov: string;                     // 检测到的视角（第一/第三人称）
  tense: string;                   // 时态
  tone: string;                    // 语气（克制/激烈/幽默/阴郁…）
  avgSentenceLength: string;       // 句长特征
  hooksDetected: string[];         // 已埋下的悬念/伏笔
  promisesToPayOff: string[];      // 后文必须兑现的钩子
}

// 风格模板（内置 + 用户自定义）
interface StyleTemplate {
  id: string;
  name: string;                    // 如"知乎盐选·悬疑反转"、"我的文风"
  category: 'builtin' | 'custom';
  pov: string;                     // 叙述视角
  tone: string;                    // 基调
  emotionArc: string;              // 情绪线设计（如：虐 → 爽 → 甜）
  structureRules: string;          // 结构规则（篇幅分配/反转密度/钩子密度）
  proseRules: string;              // 文风规则（句长/段落/对话占比/禁忌表达）
  samples: string[];               // 风格范文（few-shot 注入）
  sourceSample?: string;           // 自定义风格：用户上传的原始样本
}

// 角色
interface Character {
  id: string;
  storyId: string;
  name: string;
  role: 'protagonist' | 'antagonist' | 'love_interest' | 'supporting';
  personality: string;             // 性格标签
  background: string;              // 背景故事
  motivation: string;              // 核心动机
  characterArc: string;            // 角色弧线
  speechStyle: string;             // 说话风格（含示例台词）
  appearance: string;              // 外貌描写
  relationships: Relationship[];   // 与其他角色的关系
}

// 大纲
interface Outline {
  id: string;
  storyId: string;
  emotionCurve: EmotionPoint[];    // 情绪曲线设计
  beats: StoryBeat[];              // 故事节拍
}

interface EmotionPoint {
  position: number;                // 0.0 ~ 1.0 (故事进度)
  emotion: string;                 // 甜/虐/爽/紧张/绝望/释然
  intensity: number;               // 1-10
  description: string;
}

interface StoryBeat {
  id: string;
  order: number;
  type: 'hook' | 'setup' | 'inciting' | 'escalation' | 'reversal' | 'climax' | 'resolution';
  title: string;
  summary: string;                 // 该节拍的概要
  emotion: string;
  conflict: string;
  reversal?: string;               // 反转点
  sourceKeyPlotId?: string;        // 若该节拍来自用户剧情点，关联 KeyPlot.id
  wordCountTarget: number;
}

// 场景
interface Scene {
  id: string;
  storyId: string;
  beatId: string;
  order: number;
  setting: string;
  charactersPresent: string[];
  sceneGoal: string;
  content: string;                 // 生成的正文内容
  wordCount: number;

}

// 修订记录
interface Revision {
  id: string;
  sceneId: string;
  content: string;
  operationType: 'generate' | 'continue' | 'expand' | 'rewrite' | 'polish';
  instruction?: string;
  createdAt: Date;
}
```

### 3.4 Prompt 工程设计（核心竞争力）

#### 3.4.1 Prompt 分层组装架构

```
最终 Prompt = System指令 + 风格约束(StyleInjector) + 用户素材锚定(AnchorGuard) + 上下文(ContextAssembler) + 任务指令
```

```typescript
class PromptEngine {
  assemble(params: AssembleParams): string {
    const systemPrompt = this.templateRegistry.get(params.taskType);
    const styleBlock = this.styleInjector.inject(params.styleId);
    const anchorBlock = this.anchorGuard.build(params.story);   // 用户开头/大纲/剧情点 → 不可违背的硬约束
    const context = this.contextAssembler.build(params);
    return [systemPrompt, styleBlock, anchorBlock, context, params.userInstruction]
      .filter(Boolean)
      .join('\n\n---\n\n');
  }
}
```

**AnchorGuard（用户素材锚定）规则：**

- 用户开头 → 正文第一幕原样使用，续写必须保持视角/语气/句长一致，已埋伏笔必须兑现
- 用户大纲 → 结构化解析后作为节拍骨架，AI 只细化不偏移
- 用户剧情点 → `locked` 的剧情点必须出现在成文中且情节不走样，AI 负责点与点之间的过渡、铺垫与冲突升级

#### 3.4.2 核心 Prompt 链（级联生成 + 输入归一）

```
任意输入组合（题材 / 开头 / 大纲 / 剧情点）
    ↓ [输入归一化 Prompt]（按输入类型分支）
    │   ├─ 题材 → 故事构思
    │   ├─ 开头 → 开头分析 → 反推梗概
    │   ├─ 大纲 → 结构化解析
    │   └─ 剧情点 → 点连成线
    ↓
统一的 标题 + 梗概 + 钩子（用户可编辑）
    ↓ [角色生成 Prompt]
主角 + 对手 + 配角 + 关系图
    ↓ [大纲生成 Prompt]
情绪曲线 + 节拍表 + 伏笔追踪 + 反转设计（用户素材已锚定）
    ↓ [场景展开 Prompt]
逐场景生成正文（注入所选风格）
```

#### 3.4.3 输入归一化 Prompt（四个分支）

**A. 题材 → 故事构思**

```
根据用户给的题材/关键词，输出：
## 标题（10字以内，有悬念感或情绪冲击力）
## 导语（4-6句，第一句话就要制造悬念或冲突）
## 一句话梗概 (Logline)
## 详细梗概 (Synopsis, 500-800字，含起承转合，标注每个转折点)
## 情绪标签（选 2-3 个：甜、虐、爽、燃、虐心、治愈、暗黑）
```

**B. 开头分析与反推**

```
用户已经写好了故事开头，你的任务：
1. 分析：叙述视角、时态、语气、句长特征、对话密度
2. 找出开头已埋下的悬念/伏笔，逐条列出
3. 反推一个完整梗概：开头暗示的冲突走向何处、伏笔如何兑现、结尾如何收
4. 输出续写约束清单（后续正文必须遵守）

硬性要求：反推的梗概必须顺着开头的方向走，不得另起炉灶。
```

**C. 大纲结构化解析**

```
将用户提供的自由格式大纲解析为结构化节拍表：
- 识别出：开篇设定 / 触发事件 / 升级 / 反转 / 高潮 / 结局
- 用户已写明的内容必须原样保留为对应节拍的 summary
- 用户没写到的环节补全，并标注 [AI补全] 供用户确认
- 输出每个节拍的目标字数，总字数对齐用户目标篇幅
```

**D. 剧情点连成线**

```
用户提供了 N 个关键剧情点，按用户给定顺序：
1. 保留每个剧情点的原意（locked 的不得改动）
2. 在相邻剧情点之间补写：过渡场景、冲突铺垫、情绪递进
3. 补全开头（若用户未提供）与结局
4. 输出完整节拍表，标注哪些节拍来自用户剧情点 [用户]、哪些是补写 [AI补全]
约束：剧情点之间不允许"平推"，每段过渡必须携带新冲突或新信息。
```

#### 3.4.4 角色生成 Prompt

```
角色设计原则：
- 主角必须有"让人心疼"或"让人佩服"的特质
- 性格要有反差（如：表面温柔内心狠辣、表面高冷实则深情）
- 每个角色都有不可告人的秘密
- 对话风格要有辨识度，读者看台词就知道是谁
- 若用户开头/大纲中已出现角色，必须以用户设定为准，只补充不推翻

输出：
- 姓名/年龄/性别
- 性格标签（3个，其中必须有1个反差标签）
- 核心困境（她最害怕/最想改变什么）
- 背景故事（100字内）
- 说话风格（给2-3句示例台词）
- 外貌特征（1-2个记忆点即可）
- 角色弧线：从____变成____
- 角色关系图（表面关系 vs 真实关系）
```

#### 3.4.5 大纲生成 Prompt（含情绪曲线）

```
短篇故事结构模板（可按风格调整）：
1. 开篇钩子 (50-100字) —— 制造悬念或冲突（用户已提供开头则跳过）
2. 困境展示 (800-1200字) —— 让读者心疼/愤怒/好奇
3. 触发事件 (500-800字) —— 改变主角命运的事
4. 第一次升级 (1000-1500字) —— 主角采取行动
5. 第一个反转 (800-1200字) —— 读者以为的真相不是真相
6. 第二次升级 (1000-1500字) —— 更大的冲突
7. 第二个反转/最低点 (800-1000字) —— 看似一切都完了
8. 高潮 (1500-2000字) —— 真相大白/逆袭/复仇/和解
9. 结局 (500-800字) —— 干脆收尾或余韵悠长

输出：
- 情绪曲线表（进度/情绪/强度/发生什么）
- 节拍表（每个节拍的类型/标题/概要/冲突/反转/情绪/目标字数）
- 伏笔追踪表（伏笔/埋设位置/揭示位置/效果）—— 含用户开头中已埋的伏笔
- 反转设计详案（读者以为的真相 vs 实际真相 vs 如何铺垫 vs 揭示方式）

约束：每 800-1500 字必须有一个小高潮或反转（节奏密度按所选风格调整）
```

#### 3.4.6 场景展开正文 Prompt（最关键！）

```
你正在按【所选风格模板】写一个短篇故事。

【风格注入】（由 StyleInjector 动态注入）
- 视角/语气/句长/段落/对话占比/修辞偏好/禁忌表达/风格范文

【用户素材锚定】（由 AnchorGuard 动态注入）
- 用户开头（若有）：本场景必须与其语气、节奏无缝衔接
- 用户剧情点（若命中本场景）：必须原意呈现，不得改写
- 伏笔指令：本场景需埋设/揭示的伏笔

【通用写作规则】
- 每句话都要推动情节或传递情绪，零废笔
- 用动作和细节传递情绪，少用形容词
  ✗ "她很伤心"
  ✓ "我把手机翻了个面，屏幕朝下。不想再看那条消息了。"
- 大量使用对话推动情节，对话占比按风格模板执行
- 场景切换干脆，可以直接跳切
- 禁止弱化表达（"不禁""忍不住"）、连续感叹号、说教式旁白

场景展开时注入：
- 前文摘要 + 当前场景信息 + 角色说话风格
- 目标字数、情绪目标
```

#### 3.4.7 写作工具 Prompt

| 工具 | 核心指令 |
|------|----------|
| 续写 | 完美衔接前文语气节奏，推进情节或加深情绪，结尾留钩子 |
| 扩写 | 不改变情节，增加动作/感官/对话细节，让情绪更饱满，零废笔 |
| 改写 | 按用户指令改写（如"把甜改虐"/"让主角更强势"），保持风格一致 |
| 润色 | 不改变情节，优化节奏（长拆短）、强化情绪词、删冗余、确保对话自然 |

所有工具在执行时同样注入当前风格模板；若选中文本属于用户锚点素材，改写前需提示用户确认。

#### 3.4.8 风格分析 Prompt（自定义风格）

```
分析用户提供的样本文本，输出可直接用于写作约束的风格描述：
- 叙述视角与时态
- 句长分布（短促/绵长/交错）、段落习惯
- 对话密度与对话风格（生活化/书面化/机锋式）
- 情绪表达方式（直给/克制/借物抒情）
- 高频修辞（比喻/白描/意识流）
- 标志性用词与禁忌表达
- 提炼 3 条最具辨识度的文风特征
输出为 StyleTemplate 结构化字段，用于 StyleInjector 注入。
```

#### 3.4.9 内置风格模板示例

**模板一：知乎盐选·甜宠逆袭**
- 视角：第一人称；情绪线：虐 → 爽 → 甜
- 规则：导语钩子开篇、短句短段、前半段被欺负到极致 → 60%处逆袭转折 → 逆袭干脆利落 → 最后一幕"爽+甜"双满足
- 风格示例：

```
我签了离婚协议那天，下着雨。

他说："你配不上我。"

我笑了。

三年，我给他洗衣做饭，陪他从一穷二白到公司上市。

现在他嫌我配不上了。

我把笔一放："行，签字。不过你可能不知道一件事——你公司最大的投资人，是我爸。"

他脸色变了。

我已经不想看了。
```

**模板二：知乎盐选·悬疑反转**
- 视角：第一人称；情绪线：紧张 → 悬疑 → 震撼
- 规则：开篇有"不对劲"细节 → 每1000字至少一个线索 → 至少2次重大反转 → 最终真相让人回去找伏笔
- 风格示例：

```
我老公失踪的第七天，警察来了。

"你确定他是自愿失踪的？"

"当然。"我给他倒了杯水。

他看了看我，又看了看我的身后。

"你一个人在住？"

"是啊。"我笑了。

他没再问。

但我注意到，他在记录本上写了一行字，然后迅速翻过了一页。

我老公不知道的是，他不是第一个"失踪"的人。
```

其余内置模板（起点玄幻·热血升级 / 晋江古言·情深不寿 / 豆瓣文艺·都市情感）按同一结构定义，首期上线至少 3 个，后续每月新增 1-2 个。

### 3.5 用户交互流程

```
Step 0: 选择起步方式（可多选组合）
  □ 给题材/关键词    □ 粘贴开头
  □ 粘贴大纲/梗概    □ 列主要剧情点（逐条添加，可标记"必须保留"）
      ↓
Step 1: 选择风格
  内置风格模板（预览风格示例）/ 我的自定义风格 / 现场上传样本生成新风格
      ↓
Step 2: AI 构思与确认
  → AI 按输入类型归一化生成：标题 + 梗概 + 钩子（开头模式额外输出"开头分析报告"）
  → 用户可编辑 / 重新生成 / 调整方向
      ↓
Step 3: 角色设定
  → AI 生成主角 + 对手 + 配角 → 每个角色可编辑/重新生成
      ↓
Step 4: 大纲生成
  → AI 生成情绪曲线 + 节拍表 + 伏笔追踪（用户大纲/剧情点标注 [用户] 并锁定）
  → 可拖拽排序 / 编辑 / 解锁
      ↓
Step 5: 逐场景生成正文
  左侧：大纲/节拍导航（用户锚点素材带标记）
  右侧：编辑器（用户开头原样置顶为第一幕）
  → [生成当前场景] 或 [一键生成全部]
  → 编辑器内支持：选中文字 → 续写/扩写/改写/润色 + AI 指令框
      ↓
Step 6: 全文审阅与导出
  → 全文通读模式 → AI 全文润色（保持所选风格）→ 导出 Markdown / DOCX
```

## 五、验证方案

1. **题材模式**：创建一个"甜宠逆袭"故事，走完构思 → 角色 → 大纲 → 正文全流程
2. **开头模式**：粘贴一段自写开头，检查正文是否从用户开头无缝续写，视角/语气一致，伏笔有兑现
3. **大纲模式**：粘贴自由格式大纲，检查结构化节拍是否保留用户原意，[AI补全] 部分标注正确
4. **剧情模式**：输入 4-5 个锁定剧情点，检查成文中剧情点原意不变、过渡有冲突不平淡
5. **多风格**：同一题材分别用 3 种以上风格生成，对比文风差异是否显著
6. **自定义风格**：上传样本文本生成风格，检查生成正文是否贴近样本特征
7. 测试写作工具（续写/扩写/改写/润色）是否正常工作
8. 切换不同模型（Claude/GPT/DeepSeek），对比生成质量
9. 导出 Markdown 文件，检查格式正确性

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| AI 生成内容有"AI味" | 持续迭代风格模板，收集好/坏案例微调 prompt，可考虑 fine-tune |
| 生成质量不稳定 | 提供"重新生成"和"局部改写"能力，让用户可以精细控制 |
| AI 偏离用户素材（改了开头/剧情） | AnchorGuard 硬约束 + 生成后自动比对锚点 + 用户锚点区域改动需确认 |
| 自定义风格分析不准 | 支持多段样本输入 + 风格描述可手动编辑微调后再保存 |
| 模型 API 成本波动 | 多模型可切换，允许用户选择性价比更高的模型 |
| 未来扩展到长篇的一致性 | 预留上下文管理/检索排序机制的扩展位 |
| 内容安全 | 接入内容审核 API，过滤敏感内容 |
