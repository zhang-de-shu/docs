# 进步吧 · 产品方案

> 推送各行业的新事件。

「进步吧」是一款**行业日报聚合 App**：内置几十个可选行业/领域，用户订阅感兴趣的行业后，每天点开对应行业即可看到由 AI 定时检索生成的当日行业简报——今天这个行业发生了什么、为什么重要、一手来源在哪。定位一句话：**每天 5 分钟，跟上你关心的行业。**

---

## 一、产品定位

| 维度 | 说明 |
| --- | --- |
| 一句话定位 | 可选行业 × 每日简报：点进哪个行业，就看哪个行业的今天 |
| 目标用户 | 从业者/投资人/研究者/学生/资讯重度用户——关心"某个领域每天的变化"的人 |
| 核心问题 | 综合新闻 App 太泛、垂直媒体太散；用户想要的是"我关心的领域，每天一份高密度、有来源、有判断的简报" |
| 内容来源 | 由定时任务（skill）每日自动联网检索、筛选、结构化生成，非人工编辑 |
| 差异化 | ① 行业可自选、可组合；② 每条事件都有"事实 + 影响/原理 + 一手链接"三件套；③ 按日期归档，可回溯 |

## 三、单个行业的内容形态（每日简报标准）

每个行业每天产出一份 Markdown 简报，结构统一（参考现有三份简报）：

```text
# {领域}简报 · {日期}
> 视角 / 时间窗 / 来源口径

## 一句话概览          ← 当天最重要的 1-3 件事，30 秒读完
## 板块一（主题分类）
- **事件标题**
  - 事实/简介：发生了什么（客观陈述）
  - 影响/技术原理：为什么重要、如何解读（观点需标注"观点"）
  - 来源：[一手来源](链接) ｜ [第二来源](链接)
  - 日期：事件发生/发布时间
## 板块二 ...
---
*备注：来源口径、免责说明*
```

**内容质量红线（写进每个生产 skill 的提示词）：**

1. **一手来源优先**：官方公告 > 权威通讯社/媒体 > 行业媒体；每条事件必须有可点击链接。
2. **事实与观点分离**：事实客观陈述；机构预测、研报观点必须标注"（观点）"。
3. **争议信息标注**：战果、伤亡等单方数据标注宣称方；未经证实的信息标"待证实"。
4. **时间窗明确**：每天简报标注检索窗口与事件日期，周末/节假日规则可配置（如周一含周末外溢）。
5. **无内容不硬凑**：某板块当天无事发生，写说明而非注水。

## 四、内容生产机制

```
定时调度（每日固定时刻，按行业错峰）
   ↓
行业 skill 执行：多源联网检索（新闻、官方发布、arXiv、GitHub、交易所、社媒热榜…）
   ↓
筛选与去重：时间窗过滤 → 重要度排序 → 交叉验证
   ↓
按行业模板生成结构化简报（Markdown + 结构化 JSON 双产物）
   ↓
质量校验：链接可达性、来源数量、格式完整性 → 失败自动重试
   ↓
入库 → 推送 → App 端展示
```

- **调度时间**：按行业属性错峰。例如军情/财经早 7:00（覆盖隔夜美股），AI 前沿早 8:30（覆盖隔夜 arXiv/GitHub），文娱体育晚 22:00（覆盖当日赛果）。
- **双产物设计**：Markdown 用于阅读渲染；结构化 JSON（标题、板块、条目、来源、日期）用于搜索、收藏、跨行业关联和 AI 问答。
- **归档**：按 `行业/日期` 永久归档，形成每个行业的"编年史"。

## 五、App 设计方案

### 5.1 信息架构

```
首页（今日）
 ├── 已订阅行业卡片流：每个行业一张卡片 = 今日一句话概览 + 事件数 + 未读标记
 ├── 顶部：日期切换（看昨天及更早的"今日"）
 └── 入口：行业广场（全部 32 个领域，按九大类浏览、订阅）

行业页
 ├── 今日简报（默认）
 ├── 历史日历：按日期轴回溯该行业任意一天的简报
 ├── 板块导航：跳转到简报内各主题板块
 └── 行业档案：该行业的视角/口径说明、订阅设置（推送时间、关注板块）

简报阅读页
 ├── 一句话概览置顶
 ├── 条目卡片：标题 → 事实 → 影响/原理 → 来源按钮（内置浏览器打开）
 └── 条目操作：收藏、笔记、分享、追问

我的
 ├── 订阅管理（行业增删、排序、推送设置）
 ├── 收藏与笔记
 ├── 搜索历史 / 阅读历史
 └── 周报月报（订阅制聚合产物）
```

### 5.2 核心功能清单

| # | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| 1 | 行业订阅 | 从 32 个领域中任选，支持排序；新用户首次启动引导选 3 个 | P0 |
| 2 | 每日简报阅读 | 结构化渲染：概览、板块、条目、来源内嵌打开 | P0 |
| 3 | 每日推送 | 每个订阅行业一条通知，正文=一句话概览；推送时间可配 | P0 |
| 4 | 历史归档 | 日历视图回看任意日期简报；支持"时间轴"模式连续浏览 | P0 |
| 5 | 全文搜索 | 跨行业/行业内搜索事件、公司、人名、关键词，结果定位到具体条目 | P1 |
| 6 | 收藏与笔记 | 收藏条目、写笔记，可导出 | P1 |
| 7 | 跨行业关联 | 同一事件出现在多个行业简报中时（如"对伊制裁"同时出现在财经/军情/传统能源），显示关联标签，一键跳转 | P1 |
| 8 | AI 追问 | 基于当日/历史简报的问答："这条事件的背景是什么？""上周这个行业最重要的三件事？" | P1 |
| 9 | 周报/月报 | 自动聚合一周/一月行业大事，生成回顾长文，周末/月末推送 | P2 |
| 10 | 个性化聚焦 | 在行业内进一步勾选关注板块（如 AI 前沿里只看"智能体+具身智能"），推送和首页只高亮相关内容 | P2 |
| 11 | 分享卡片 | 条目/概览生成分享图，带 App 水印 | P2 |
| 12 | 行业申请 | 用户提交想看的行业，需求聚合成上线排期依据 | P2 |

### 5.3 页面要点

**首页**：卡片流设计，每张卡片三行以内——行业名 + 一句话概览 + "8 条 · 2 条重要"。全部读完 < 1 分钟，决定今天深入哪个行业。深色/浅色主题，信息密度优先、无信息流广告。

**行业页**：顶部是"今日"大字报式概览，下面是可折叠的板块目录；右滑或点"历史"进入日期轴（横向日历条，有简报的日期带圆点）。

**简报阅读页**：条目卡片化。默认只展开"标题 + 简介"，点开后展开影响/原理；来源以图标按钮呈现（一手来源高亮）。重要事件（本期大事）带标记并置顶于概览。

### 5.4 数据模型（核心表）

```text
Industry（行业）        : id, 名称, 大类, 简介, 口径说明, 状态, 排序权重, 调度配置
Briefing（简报）        : id, industry_id, 日期, 概览, markdown 原文, 结构化 JSON, 状态(草稿/已发布/失败)
Entry（条目）           : id, briefing_id, 板块, 标题, 简介, 影响/原理, 日期, 是否大事, 关联事件组
Source（来源）          : id, entry_id, 名称, URL, 类型(一手/转引/观点)
Subscription（订阅）    : user_id, industry_id, 推送时间, 关注板块
Collection/Note（收藏笔记）: user_id, entry_id, 内容, 时间
EventGroup（跨行业关联）  : id, 事件名, entry_id 列表        ← 由生成管线或离线任务标注
```

### 5.5 技术架构建议

| 层 | 方案 |
| --- | --- |
| 客户端 | 跨端框架（Flutter / React Native）或先做小程序验证；重阅读场景，渲染器需支持 Markdown + 结构化条目两种视图 |
| 后端 | 常规 REST/GraphQL API：订阅、简报分发、搜索、用户；鉴权用手机号/微信登录 |
| 内容管线 | 复用现有 skill 体系：定时任务按行业调度 → 检索生成 → 产出 MD+JSON → 质检 → 写入对象存储 + 数据库；失败重试与人工兜底告警 |
| 存储 | 简报原文放对象存储；条目/来源/用户数据放关系库；搜索走全文索引（ES / Meilisearch） |
| 推送 | APNs / FCM / 厂商通道；推送内容 = 行业名 + 一句话概览，点击直达简报页 |
| AI 问答 | 以当日+近 30 天简报为上下文的 RAG；答案附条目引用，可跳回原文 |

### 5.6 与现有能力的关系

现在 `00-每日简报` 目录下的三个行业（AI 前沿、财经、军情）+ 三个已就绪的 skill（ai-progress-tracker / finance-news-tracker / military-news-tracker）就是 App 的**内容原型与生产线样板**：App 要做的本质上是把"个人本地简报目录"产品化为"多用户可订阅的简报服务"。

| MVP（4-6 周） | 6-8 个行业（3 个已接入 + 半导体、国际政治、创新药、新能源、消费）；订阅 + 阅读 + 推送 + 历史归档 | 验证"每日行业简报"的留存价值 |
| V1.0 | 行业扩到 20+；搜索、收藏笔记、跨行业关联 | 内容广度成型，形成日常使用习惯 |
| V2.0 | 32 行业全量；AI 追问、周报月报、个性化聚焦、行业申请 | 从"阅读工具"升级为"行业情报助手" |
| 远期 | 用户自定义行业（自定义关键词+板块）、团队版（共享行业看板）、简报开放 API | 平台化 |

## 七、关键指标

- **北极星**：订阅 ≥3 个行业的用户中，周活跃阅读天数（目标 ≥5 天/周）
- 次留 / 7 日留存；推送打开率；人均日阅读行业数；条目来源点击率（衡量内容可信度价值）；收藏率（衡量深度价值）

---

*一句话总结：进步吧 = 32 个行业的每日 AI 简报 + 订阅制推送 + 可回溯的行业编年史。*
