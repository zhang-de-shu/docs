# 进步吧 · 产品方案

> 推送各行业的新事件。

「进步吧」是一款**每日情报聚合 App**：用户既可以**按生活场景**订阅（我要买车、我要买房、我想理财……），也可以**按行业**订阅（半导体、AI、财经……）。每天打开，就能看到自己关心的事今天发生了什么、对自己意味着什么、一手来源在哪。定位一句话：**每天 5 分钟，跟上你关心的事。**

---

## 一、产品定位

| 维度 | 说明 |
| --- | --- |
| 一句话定位 | 按场景/行业订阅每日简报：你关心什么，就每天推什么 |
| 两类用户 | ① **普通用户**：带着生活目标来——"我想买车"，想知道车价、补贴、新车动态；② **专业用户**：带着职业需求来——从业者/投资人/研究者，想跟某个行业每天的变化 |
| 核心问题 | 综合新闻太泛、垂直媒体太散，而且都是"行业语言"；普通用户需要的是"我这件人生大事，每天的最新情况 + 对我有什么用" |
| 内容来源 | 定时任务（skill）每日自动联网检索、筛选、结构化生成，非人工编辑 |
| 差异化 | ① 场景 + 行业双入口，小白和专业用户都好用；② 每条事件"事实 + 对我/对行业的影响 + 一手链接"三件套；③ 按日期归档，可回溯 |

---

## 二、怎么选：场景入口 + 行业入口

这是本产品最关键的设计：**不让普通用户面对"行业"这个专业概念做选择**。

### 2.1 两种选择方式

```
┌─ 按场景选（推荐给普通用户）
│   "你最近在忙什么大事？"
│   → 买车 / 买房 / 装修 / 理财 / 看病 / 生娃育儿 / 孩子教育 / 求职跳槽 / 旅游 / 创业…
│   → 每个场景背后 = 一组行业 + 消费者视角
│
└─ 按行业选（面向专业用户）
    32+ 个行业目录，按九大类浏览
    → 每个行业 = 从业者视角
```

首次启动引导先问"你最近在忙什么大事？"（场景卡片），再给一个"想按行业看？"的次级入口。

### 2.3 示例：一个想买车的人怎么用

```
首次启动 → 选"我要买车" → 一键订阅（背后 = 汽车行业 · 消费者视角）
   ↓
每天早 8 点收到推送："今日汽车简报：某品牌主力车型官降 1.2 万；
购置税补贴 9 月 30 日截止；某新款今日发布"
   ↓
点进去看条目：事实 + 【对买车人】影响 + 一手来源链接
   ↓
关键节点提醒：补贴截止倒计时、关注车型降价/发布时强提醒
   ↓
买完车 → 场景可一键切换为"用车"（召回、保险、油价）或退订
```

场景是**阶段性的**：大事办完了，场景可以"毕业"（归档），这正是"进步吧"的含义——每办成一件大事，就进步一步。

## 四、单个行业的内容形态（每日简报标准）

### 4.1 视角机制：同一行业，两种读法

同一份行业素材，按订阅视角生成不同版本：

| | 从业者视角（按行业订阅默认） | 消费者视角（按场景订阅默认） |
| --- | --- | --- |
| 立场 | 行业内部人：竞争、数据、政策、技术趋势 | 办事的人：价格、时机、补贴、避坑、对我有什么用 |
| 条目结构 | 事实 + 影响/技术原理 + 来源 | 事实 + **对{场景用户}的影响/行动建议** + 来源 |
| 板块侧重 | 产业数据、供应链、公司动态、政策 | 价格行情、政策节点、产品上新、质量/口碑预警 |

**示例：汽车行业，同一天同一事件**

- 从业者视角：`某品牌 8 月销量 12 万台（+18%）→ 份额变化与供应链影响 → 来源`
- 消费者视角（买车场景）：`某品牌主力车型官降 1.2 万 →【对买车人】主力配置现车充足，是近半年低点，可到店比价 → 来源`

### 4.2 简报统一结构

```text
# {领域}简报 · {日期}（{视角}）
> 视角 / 时间窗 / 来源口径

## 一句话概览          ← 当天最重要的 1-3 件事，30 秒读完
## 板块一（主题分类）
- **事件标题**
  - 事实/简介：发生了什么（客观陈述）
  - 影响/对{用户}的意义：为什么重要、该怎么办（观点需标注"观点"）
  - 来源：[一手来源](链接) ｜ [第二来源](链接)
  - 日期：事件发生/发布时间
## 板块二 ...
---
*备注：来源口径、免责说明*
```

### 4.3 内容质量红线（写进每个生产 skill 的提示词）

1. **一手来源优先**：官方公告 > 权威通讯社/媒体 > 行业媒体；每条事件必须有可点击链接。
2. **事实与观点分离**：事实客观陈述；机构预测、研报观点必须标注"（观点）"。
3. **争议信息标注**：战果、伤亡等单方数据标注宣称方；未经证实的信息标"待证实"。
4. **时间窗明确**：每天简报标注检索窗口与事件日期，周末/节假日规则可配置。
5. **无内容不硬凑**：某板块当天无事发生，写说明而非注水。
6. **消费者视角不夹带营销**：只给事实与建议依据，不给具体导购结论。

## 五、内容生产机制

```
定时调度（每日固定时刻，按行业错峰）
   ↓
行业 skill 执行：多源联网检索（新闻、官方发布、arXiv、GitHub、交易所、社媒热榜…）
   ↓
筛选与去重：时间窗过滤 → 重要度排序 → 交叉验证
   ↓
按视角生成简报：同一素材 → 从业者版 / 消费者版（Markdown + 结构化 JSON 双产物）
   ↓
质量校验：链接可达性、来源数量、格式完整性 → 失败自动重试
   ↓
入库 → 按订阅分发推送 → App 端展示
```

- **调度时间**：按内容属性错峰。军情/财经早 7:00（覆盖隔夜美股），AI 前沿早 8:30（覆盖隔夜 arXiv/GitHub），消费类场景简报早 8:00（通勤可读）。
- **双产物设计**：Markdown 用于阅读渲染；结构化 JSON（标题、板块、条目、来源、日期、视角）用于搜索、收藏、跨行业关联、场景提醒和 AI 问答。
- **归档**：按 `行业/日期/视角` 归档，形成每个行业的"编年史"。

## 六、App 设计方案

### 6.1 信息架构

```
首页（今日）
 ├── 关注流：已订阅场景/行业的卡片流
 │    每张卡片 = 今日一句话概览 + 事件数 + 未读标记
 ├── 顶部：日期切换（看昨天及更早的"今日"）
 └── 广场（双入口）
      ├── 场景广场："你最近在忙什么大事？"14 个场景卡片 + 自定义场景
      └── 行业广场：34 个领域按九大类浏览、订阅

场景页 / 行业页
 ├── 今日简报（默认）
 ├── 历史日历：按日期轴回溯任意一天的简报
 ├── 板块导航：跳转到简报内各主题板块
 └── 订阅设置（推送时间、关注板块、视角切换）

简报阅读页
 ├── 一句话概览置顶
 ├── 条目卡片：标题 → 事实 → 影响/建议 → 来源按钮（内置浏览器打开）
 └── 条目操作：收藏、笔记、分享、追问、设提醒

我的
 ├── 订阅管理（场景 + 行业统一管理、排序、推送设置）
 ├── 我的大事时间线：订阅过的场景与"毕业"记录
 ├── 收藏与笔记
 └── 周报月报（聚合产物）
```

### 6.2 核心功能清单

| # | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| 1 | 场景订阅 | 从场景广场选择生活目标，自动映射行业+视角；新用户首启引导 | P0 |
| 2 | 行业订阅 | 34 个行业目录任选，从业者视角 | P0 |
| 3 | 每日简报阅读 | 结构化渲染：概览、板块、条目、来源内嵌打开 | P0 |
| 4 | 每日推送 | 每个订阅一条通知，正文=一句话概览；推送时间可配 | P0 |
| 5 | 关键节点提醒 | 场景相关的时间节点强提醒：补贴截止倒计时、关注车型降价/发布、考试日期、签证新政生效日 | P1 |
| 6 | 历史归档 | 日历视图回看任意日期简报；支持时间轴连续浏览 | P0 |
| 7 | 全文搜索 | 跨行业/场景搜索事件、公司、人名、关键词，定位到具体条目 | P1 |

| 9 | 跨行业关联 | 同一事件出现在多个简报中时（如"对伊制裁"同时在财经/军情/传统能源），显示关联标签一键跳转 | P1 |
| 10 | AI 追问 | 基于当日/历史简报的问答："补贴怎么领最划算？""上周车价有什么变化？" | P1 |
| 11 | 周报/月报 | 自动聚合一周/一月大事，生成回顾长文推送 | P2 |
| 12 | 场景毕业与切换 | 大事办完一键归档场景，保留纪念时间线；推荐下一个相关场景（买车→用车） | P2 |
| 13 | 自定义场景 | 自然语言描述目标，AI 生成行业组合与视角 | P2 |
| 14 | 分享卡片 | 条目/概览生成分享图 | P2 |

### 6.3 页面要点

**首页**：卡片流设计，每张卡片三行以内——场景/行业名 + 一句话概览 + "8 条 · 2 条与你相关"。全部读完 < 1 分钟，决定今天深入哪个。深色/浅色主题，信息密度优先、无信息流广告。

**广场**：场景广场是产品门面——大卡片、生活化文案（"要不要现在买车？""房贷利率又降了？"）；行业广场偏专业冷静，九大类目录。

**简报阅读页**：条目卡片化，默认只展开"标题 + 简介"，点开展开影响/建议；来源以图标按钮呈现（一手来源高亮）。消费者视角条目的影响句统一用"对买车人/买房人/…"开头，一眼看出与我何干。

### 6.4 数据模型（核心表）

```text
Scenario（场景）        : id, 名称, 文案, 行业组合, 默认视角, 排序
Industry（行业）        : id, 名称, 大类, 简介, 口径说明, 状态, 调度配置
Briefing（简报）        : id, industry_id, 视角, 日期, 概览, markdown, 结构化 JSON, 状态
Entry（条目）           : id, briefing_id, 板块, 标题, 事实, 影响, 日期, 是否大事, 关联事件组
Source（来源）          : id, entry_id, 名称, URL, 类型(一手/转引/观点)
Subscription（订阅）    : user_id, 类型(场景/行业), 对象id, 视角, 推送时间, 关注板块, 状态(进行中/毕业)
Reminder（节点提醒）    : user_id, entry_id/场景id, 提醒时间, 类型(倒计时/触发)
Collection/Note（收藏笔记）: user_id, entry_id, 内容, 时间
EventGroup（跨行业关联）  : id, 事件名, entry_id 列表
```

### 6.5 技术架构建议

| 层 | 方案 |
| --- | --- |
| 客户端 | 跨端框架（Flutter / React Native）或先做小程序验证；重阅读场景，渲染器支持 Markdown + 结构化条目两种视图 |
| 后端 | 常规 REST/GraphQL API：订阅、简报分发、搜索、提醒、用户；鉴权用手机号/微信登录 |
| 内容管线 | 复用现有 skill 体系：定时任务按行业调度 → 检索生成 → 产出双视角 MD+JSON → 质检 → 写入对象存储 + 数据库；失败重试与告警 |
| 存储 | 简报原文放对象存储；条目/来源/用户数据放关系库；搜索走全文索引（ES / Meilisearch） |
| 推送 | APNs / FCM / 厂商通道；常规推送 = 一句话概览，节点提醒独立通道强提醒 |
| AI 问答 | 以当日+近 30 天简报为上下文的 RAG；答案附条目引用，可跳回原文 |

### 6.6 与现有能力的关系

`00-每日简报` 下的三个行业（AI 前沿、财经、军情）+ 三个已就绪的 skill（ai-progress-tracker / finance-news-tracker / military-news-tracker）是**内容原型与生产线样板**。App 要做的是把这个本地简报目录产品化为多用户订阅服务，并加上"场景→行业+视角"这一层面向普通用户的翻译层。
