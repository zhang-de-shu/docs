# 数据工程手册

> 面向工程师的 LLM 数据工程实战手册。讲清楚训练数据**从哪来、怎么洗、怎么配、怎么去重去污染**,以及后训练的**指令/偏好数据怎么合成和筛选**。一句话:**模型的上限是数据的上限**。
>
> 范围说明:本文覆盖**预训练数据管线**与**后训练(SFT/偏好)数据构造**两条线。它是《预训练原理与技巧》《SFT训练技巧》《PPO-GRPO-DPO》的数据底座,Agent 轨迹数据见《Agentic-SFT训练技巧》。
>
> ⚠️ 客观性提示:数据配方高度依赖目标能力与语料,厂商常不公开关键细节,**最优配方请在自己的评估集上做消融**。

## 0. 全景:数据为什么是第一杠杆

在架构和算力趋同的今天,**模型间的差距越来越多来自数据**。围绕数据有几对核心矛盾:

| 矛盾 | 解法 | 作用 |
|------|------|------|
| 网页数据海量但脏 | **多级过滤管线(FineWeb 式)** | 质量 > 数量 |
| 数据有大量重复 | **去重(MinHash/精确)** | 防记忆、提效率 |
| 训练集混进评测题 | **去污染(decontamination)** | 防分数虚高 |
| 人工标指令/偏好太贵 | **合成数据(Self-Instruct/Magpie)** | 规模化 |
| 合成数据有噪声 | **数据筛选(质量/多样性/影响力)** | 少而精 |

> **核心原则**:**Garbage in, garbage out**。预训练靠"大规模高质量过滤",后训练靠"小规模精挑细选"——LIMA 用 1000 条精选指令就达到很强对齐,证明后训练阶段**质量和多样性远比数量重要**。数据工程的本质是"在海量噪声里捞出高信号"。

---

## 1. 预训练数据管线:FineWeb 范式

现代开放数据集(FineWeb、Nemotron-CC、DCLM)确立了一套标准多级管线。

### 1.1 标准流程

```
原始 Common Crawl(WARC/WET)
  → 文本提取(trafilatura 等,去 HTML 样板)
  → 语言识别(按目标语种过滤)
  → 规则过滤(Gopher/C4 启发式:去过短、符号过多、重复行)
  → 去重(MinHash 近似去重)
  → 质量过滤(分类器:像不像"高质量文本")
  → 去污染(剔除评测基准)
  → PII 处理
```

### 1.2 关键洞察:过滤决定一切

> **FineWeb 的核心结论:精心设计的过滤和去重,比单纯堆数据量更能提升下游表现。同样来自 Common Crawl,过滤管线的差异造成模型能力的巨大差距。**

- **规则过滤**(启发式):去掉明显垃圾——行太短、标点异常、重复段、关键词黑名单;
- **模型过滤**(分类器):训一个分类器判"这段文本像不像 Wikipedia/教科书那种高质量文本",DCLM 证明**基于模型的质量过滤是单点最大杠杆**;
- **FineWeb-Edu**:用"教育价值"打分过滤,在知识类基准上大幅提升——说明**针对目标能力定制过滤标准**很有效。

### 1.3 Nemotron-CC:别只要"高质量"

> **激进的质量过滤会扔掉太多数据,损害数据量。Nemotron-CC 的做法:对低质量数据做改写(rephrasing)回收、对高质量数据做合成扩充,在"质量"和"数量"间取平衡。** 把"过滤"变成"过滤 + 改造"。

---

## 2. 去重(Deduplication):防记忆、提效率

### 2.1 为什么必须去重

- 网页有大量重复(模板、转载、镜像);
- 重复数据让模型**死记硬背**(memorization)、浪费算力、可能加剧隐私泄露;
- 适度去重能提升训练效率和泛化。

### 2.2 方法

- **精确去重**:哈希整段/文档,删完全相同的;
- **近似去重(MinHash + LSH)**:用 MinHash 估计文档间 Jaccard 相似度,LSH 分桶快速找近重复——这是大规模标配;
- **粒度**:文档级 vs 段落级,各有取舍(段落级更激进,可能破坏连贯性)。

> 注意:去重不是越狠越好。过度去重会删掉合理的重复(常见表达、模板化但有用的内容),需要在"去冗余"和"保覆盖"间平衡。

---

## 3. 去污染(Decontamination):评估可信的前提

> **训练集里如果混进了评测基准(MMLU/GSM8K 等)的题目,分数会虚高且不预测真实能力。必须在训练前把基准样本从训练集剔除。**

- 方法:n-gram 重叠匹配(训练样本和基准题有长 n-gram 重合就剔除)、embedding 相似度匹配;
- 难点:污染是**结构性**的(模型会看到能找到的一切),不可能 100% 干净,但必须尽力;
- 这直接关系评估可信度(详见《LLM与Agent评估专项手册》第 2 节)。

## 4. 数据配比(Data Mixture):配方就是能力

### 4.1 配比决定能力分布

代码/数学/多语种/网页的比例,直接决定模型的能力侧重。拍脑袋定配比是常见错误。

### 4.2 自动搜配比

- **DoReMi**:用一个小代理模型,通过 group DRO 自动学习各 domain 的最优权重,再用到大模型训练;
- **RegMix**:把"数据配比→性能"建模成回归问题,训一批小模型拟合,预测最优配比;
- 共识:**用小规模实验搜配比,别在大 run 上赌**。

### 4.3 课程与分阶段

把数据按训练阶段分层:主体用通用网页,**退火/mid-training 阶段换上高质量 + 推理 + 代码数据**(见《预训练原理与技巧》2.4)。

---

## 5. 后训练数据:指令数据合成

人工写指令-回答对太贵,合成是主流。

### 5.1 Self-Instruct 系:从种子自举

> **Self-Instruct:用少量种子指令,让强模型"生成更多新指令 + 对应回答",自举出大规模指令集。** Alpaca 用它从 175 条种子 + GPT 生成出 52K 指令,开启了开源指令微调潮。

### 5.2 Evol-Instruct:让指令变难变多样

> **WizardLM 的 Evol-Instruct:用 LLM 把简单指令"进化"——加约束、加深度、加推理步、换场景,生成更复杂多样的指令。** 解决 Self-Instruct 指令偏简单的问题。

### 5.3 Magpie:零种子自合成

> **Magpie 的巧思:对齐过的模型只给"对话模板的前缀"(没有任何指令),它会自己"补全"出一个用户指令;再让它回答。完全自动、无需种子,大规模生成高质量指令对。**

### 5.4 蒸馏(distillation)

用强模型(GPT-4/Claude)的输出训小模型——简单有效但有合规/许可风险,且会继承强模型的偏差和错误。

---

## 6. 数据筛选(Data Selection):少而精

合成出一大堆后,**筛选比生成更关键**——LIMA 证明 1000 条精选 > 海量噪声。

### 6.1 三个筛选维度

| 维度 | 怎么做 |
|------|--------|
| **质量** | 用 reward model / LLM-judge 给样本打分,留高分(如 AlpaGasus 用 GPT 打分筛 Alpaca) |
| **多样性** | 去语义近重复,覆盖任务/难度/领域(嵌入聚类、保证分布广) |
| **影响力** | 选对目标任务"最有用"的样本(LESS 用梯度影响估计) |

### 6.2 代表方法

- **AlpaGasus**:用 LLM 给指令数据打质量分,9K 精选 > 52K 全量;
- **LESS**:基于梯度的影响力估计,选对目标任务最有帮助的子集;
- **DEITA**:综合复杂度 + 质量 + 多样性的评分筛选。

> 实践纪律:**先保证多样性覆盖,再在每类里挑质量最高的**——只挑质量不管多样性会偏科。

---

## 7. 偏好数据:对齐的燃料

(用于 DPO/PPO/GRPO,见《PPO-GRPO-DPO训练技巧》)

- **构造**:同一 prompt 采多个回答,用人工或 reward model / LLM-judge 标"哪个更好"(chosen/rejected);
- **质量 > 数量**:噪声偏好对会直接教坏模型(DPO 对噪声标签敏感);
- **覆盖难度梯度**:chosen 和 rejected 的差距要有区分度——差距太小学不到,太大没信息量;
- **on-policy 更好**:用当前模型自己生成的回答构造偏好对(而非别的模型),分布更匹配(iterative/online DPO)。

## 8. 常见坑汇总(速查)

| 坑 | 说明 | 对策 |
|----|------|------|
| 只堆数据量 | 噪声拖垮质量 | 多级过滤,质量优先 |
| 不去重 | 模型死记、浪费算力 | MinHash 近似去重 |
| 不去污染 | 评测分虚高 | n-gram/embedding 剔除基准 |
| 过度过滤/去重 | 数据量塌、覆盖丢 | 平衡;低质数据改写回收 |
| 拍脑袋定配比 | 能力偏科 | DoReMi/RegMix 自动搜 |
| 合成数据照单全收 | 含噪声 | 质量+多样性+影响力筛选 |
| 只挑高质量 | 偏科、多样性差 | 先保多样性再挑质量 |
| 偏好对有噪声 | 教坏对齐 | 严控标注质量,差距适中 |
| 蒸馏不看许可 | 合规风险 | 确认数据/模型许可 |
| 后训练堆量 | 边际收益低还可能变差 | 少而精(LIMA 启示) |

## 9. 推荐实操流程(端到端)

**预训练数据:**
1. 采集(Common Crawl/领域语料)→ 文本提取 → 语言过滤;
2. 规则过滤(启发式)+ 模型质量过滤(分类器,针对目标能力定制);
3. MinHash 去重 + 评测基准去污染 + PII 处理;
4. DoReMi/RegMix 搜 domain 配比;分阶段课程(退火喂高质量)。

**后训练数据:**
5. 指令合成:Self-Instruct/Evol-Instruct/Magpie 起量,或精标种子;
6. 筛选:质量(LLM-judge 打分)+ 多样性(去重覆盖)+ 影响力(LESS),少而精;
7. 偏好数据:同 prompt 多回答 + 标注 chosen/rejected,控噪声、保区分度,优先 on-policy;
8. 全程对照评估集做消融,别信通用配方。

---

## 10. 一句话总结

数据工程的精髓:**模型上限即数据上限——预训练靠"大规模多级过滤 + 去重去污染"在噪声里捞高质量(质量过滤是最大单点杠杆),后训练靠"合成起量 + 质量/多样性/影响力三维筛选"做到少而精(1000 条精选胜过万条噪声);配比用小模型实验自动搜而非拍脑袋。** 最大的杠杆是**过滤/筛选的质量**,最大的陷阱是**只看数量**和**训练集混进评测题**。
