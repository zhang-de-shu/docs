# 数据工程手册

> 面向工程师的 LLM 数据工程实战手册。讲清楚训练数据**从哪来、怎么洗、怎么配、怎么去重去污染**,以及后训练的**指令/偏好数据怎么合成和筛选**。一句话:**模型的上限是数据的上限**。
>
> 范围说明:本文覆盖**预训练数据管线**与**后训练(SFT/偏好)数据构造**两条线。它是《预训练原理与技巧》《SFT训练技巧》《PPO-GRPO-DPO》的数据底座,Agent 轨迹数据见《Agentic-SFT训练技巧》。
>
> ⚠️ 客观性提示:数据配方高度依赖目标能力与语料,厂商常不公开关键细节,**最优配方请在自己的评估集上做消融**。

## 0. 全景:数据为什么是第一杠杆

在架构和算力趋同的今天,**模型间的差距越来越多来自数据**。围绕数据有几对核心矛盾:

| 矛盾 | 解法 | 作用 |
|------|------|------|
| 网页数据海量但脏 | **多级过滤管线(FineWeb 式)** | 质量 > 数量 |
| 数据有大量重复 | **去重(MinHash/精确)** | 防记忆、提效率 |
| 训练集混进评测题 | **去污染(decontamination)** | 防分数虚高 |
| 人工标指令/偏好太贵 | **合成数据(Self-Instruct/Magpie)** | 规模化 |
| 合成数据有噪声 | **数据筛选(质量/多样性/影响力)** | 少而精 |

> **核心原则**:**Garbage in, garbage out**。预训练靠"大规模高质量过滤",后训练靠"小规模精挑细选"——LIMA 用 1000 条精选指令就达到很强对齐,证明后训练阶段**质量和多样性远比数量重要**。数据工程的本质是"在海量噪声里捞出高信号"。

## 1. 预训练数据管线:FineWeb 范式

现代开放数据集(FineWeb、Nemotron-CC、DCLM)确立了一套标准多级管线。

### 1.1 标准流程

```
原始 Common Crawl(WARC/WET)
  → 文本提取(trafilatura 等,去 HTML 样板)
  → 语言识别(按目标语种过滤)
  → 规则过滤(Gopher/C4 启发式:去过短、符号过多、重复行)
  → 去重(MinHash 近似去重)
  → 质量过滤(分类器:像不像"高质量文本")
  → 去污染(剔除评测基准)
  → PII 处理
```

### 1.2 关键洞察:过滤决定一切

> **FineWeb 的核心结论:精心设计的过滤和去重,比单纯堆数据量更能提升下游表现。同样来自 Common Crawl,过滤管线的差异造成模型能力的巨大差距。**

- **规则过滤**(启发式):去掉明显垃圾——行太短、标点异常、重复段、关键词黑名单;
- **模型过滤**(分类器):训一个分类器判"这段文本像不像 Wikipedia/教科书那种高质量文本",DCLM 证明**基于模型的质量过滤是单点最大杠杆**;
- **FineWeb-Edu**:用"教育价值"打分过滤,在知识类基准上大幅提升——说明**针对目标能力定制过滤标准**很有效。

### 1.3 Nemotron-CC:别只要"高质量"

> **激进的质量过滤会扔掉太多数据,损害数据量。Nemotron-CC 的做法:对低质量数据做改写(rephrasing)回收、对高质量数据做合成扩充,在"质量"和"数量"间取平衡。** 把"过滤"变成"过滤 + 改造"。

### 1.4 决策细节与判据:规则过滤的具体阈值

启发式规则的经典来源是 **Gopher**(Rae et al. 2021)和 **C4**,RedPajama-V2 给出了可直接照搬的数值实现。

| 规则 | Gopher/RedPajama-V2 阈值 | 触发即剔除 |
|------|--------------------------|-----------|
| 词数 | 在 **[50, 10000]** 之外 | 太短无信息 / 太长多为爬虫垃圾 |
| 平均词长 | 在 **[3, 10]** 字符之外 | 异常说明是代码乱码或拼接 |
| 符号/词比(# 与 … 等) | **> 0.1** | 符号过多 = 非自然语言 |
| 以项目符号开头的行比例 | **> 90%**(TextDescriptives 用 0.8) | 整篇是列表 = 低信息 |
| 以省略号结尾的行比例 | **> 0.3** | 多为截断/采集失败 |
| 停用词数量 | **< 2** 个常见停用词 | 不含停用词多半不是自然语言 |
| 重复行/段/n-gram 占比 | 如某重复行占字符 **> 30%** | Gopher 列了 13 项重复阈值(见原文 Table A1) |

> **为什么用这些阈值**:它们都是"非自然语言/低信息"的代理信号。Gopher 发现**文档内过度重复**与无信息内容强相关,因此专门用一组重复指标(行、段、n-gram 多个层级)兜底,而不只看长度和符号。

### 1.5 决策细节与判据:分类器过滤何时上、强度怎么定

**何时从"规则"升级到"分类器"**:规则只能去掉明显垃圾(语言层),要进一步分"高质量 vs 普通"必须上模型。DCLM 证明**基于模型的质量过滤是单点最大杠杆**。

**FineWeb-Edu 的可执行判据(教育质量评分):**

- 用 Llama-3-70B 对 ~46 万样本打 **0~5 分**的教育价值,训练一个回归分类器(Snowflake-arctic-embed + 回归头);
- **过滤阈值取 int_score ≥ 3**:这是官方推荐值,在该阈值上 F1=82%;
- **为什么是 3 而不是更高**:阈值 > 3 虽然提升 MMLU 等知识/推理基准,但**显著拖垮 HellaSwag/PIQA**(常识)——3 是知识与常识的最佳折中;
- **过滤强度的代价**:阈值 3 会删掉 **92%** 数据(剩 1.3T tokens);想保数据量可降到阈值 2(剩 5.4T,效果略逊但仍优于 FineWeb)。

**fastText vs LLM/BERT 分类器,何时用哪个:**

| 维度 | LLM/BERT 分类器(FineWeb-Edu) | fastText 分类器(Ultra-FineWeb) |
|------|-------------------------------|--------------------------------|
| 算力 | 过滤 15T tokens 需 **~6000 H100 时** | 80 CPU、**~1000 小时**,无需 GPU |
| 精度 | 高分段(3/4/5)更准 | 0/1/2 可比,**3 分以上有衰减** |
| 何时用 | 离线一次性、追求最高质量 | 在线随训随滤、超大规模、预算有限 |

Ultra-FineWeb 的 fastText 超参可直接参考:**向量维度 256、学习率 0.1、词 n-gram 最大 3、最小词频 5、3 epoch,推理阈值 0.5**;在英文指标上比 FineWeb +3.61、比 FineWeb-Edu +1.3。

> **过滤强度的总判据**:针对**目标能力**定制过滤标准(教育/代码/推理),并在**自己的评估集上扫阈值**——同一管线,阈值高一档可能换来知识基准涨、常识基准跌。激进过滤适合短中程训练(≤15T);长程(≥15T)训练要像 Nemotron-CC 那样保住独特 token 总量、用改写回收低质数据。

## 2. 去重(Deduplication):防记忆、提效率

### 2.1 为什么必须去重

- 网页有大量重复(模板、转载、镜像);
- 重复数据让模型**死记硬背**(memorization)、浪费算力、可能加剧隐私泄露;
- 适度去重能提升训练效率和泛化。

### 2.2 方法

- **精确去重**:哈希整段/文档,删完全相同的;
- **近似去重(MinHash + LSH)**:用 MinHash 估计文档间 Jaccard 相似度,LSH 分桶快速找近重复——这是大规模标配;
- **粒度**:文档级 vs 段落级,各有取舍(段落级更激进,可能破坏连贯性)。

> 注意:去重不是越狠越好。过度去重会删掉合理的重复(常见表达、模板化但有用的内容),还会**改变数据集分布**——可能让模型在某些主题上过拟合而非泛化,需要在"去冗余"和"保覆盖"间平衡。

### 2.3 决策细节与判据:MinHash 参数怎么定

MinHash 的核心可调参数有四个,业界主流配置如下表(数字均有出处,见参考来源)。

| 参数 | 含义 | 主流取值 | 出处与判据 |
|------|------|----------|-----------|
| **Jaccard 阈值 T** | 相似度超过 T 判为重复 | **0.7~0.9**,中间值 0.8 | SlimPajama/RedPajama-V2 用 **0.8**;FineWeb 教程与 BigCode 用 **0.7**;Distilabel 默认 **0.9**。T 越低抓到的重复越多(召回高、精度低) |
| **num_perm**(排列数 / 哈希函数数) | 签名长度,控制估计精度 | **128~256** | datasketch 默认 **128**;RedPajama-V2 用 **128**;BigCode 用 **256**。越大越准但越慢(复杂度对 num_perm 线性) |
| **n-gram / shingle 大小** | 切分文档的粒度 | 字符级 **5~9**;或词级 5;SlimPajama 用 **13-gram** | LLM 管线常用字符级 **5-gram**(对改写/同义替换鲁棒);SlimPajama 在**小写去标点后的 13-gram** 上构造签名 |
| **bands / rows(LSH 分桶)** | 由 T 反推,权衡召回与精度 | 由 datasketch 按 T 计算 | 阈值不是直接卡在候选生成阶段,而是**编码进 banding 方案**:band 越多召回越高、误判越多 |

> **为什么字符级 5-gram 是好默认**:它对轻微改写、同义词替换鲁棒——既不像精确哈希那样一个字不同就漏掉,也不像太大的 n-gram 那样过度敏感。实践中常用"已知近重复对能否拿到高 Jaccard 分"来经验性地定 k。

**精确去重 vs 模糊去重,何时用哪个:**

| 场景 | 选择 | 理由 |
|------|------|------|
| 完全相同的文档/段落(镜像、转载) | **精确去重**(整段哈希) | 最快最省,先用它清掉一大批 |
| 模板化、改写、部分重叠 | **MinHash + LSH 近似去重** | 精确哈希抓不到"几乎一样";大规模标配 |
| 跨数据源去重(如 CC 与 GitHub 交叉) | **全局 MinHash**(跨源而非源内) | SlimPajama 做法:全局去重命中最重的就是 CC 和 GitHub 的跨源重叠 |

**去重粒度怎么选:**

- **文档级**:保连贯性、风险低,是默认;
- **段落级**:更激进,能清掉"文档大部分独特、但夹带通用样板段"的情况,但**可能破坏上下文连贯**——慎用,适合样板污染严重的源。

> **工程纪律**:LLM 去重不追求完美。漏掉少量近重复对的代价,远小于"为验证所有对"的算力开销——允许一定假阴性,优先把绝大部分冗余清掉。先精确去重打底,再 MinHash 近似去重补刀。

## 3. 去污染(Decontamination):评估可信的前提

> **训练集里如果混进了评测基准(MMLU/GSM8K 等)的题目,分数会虚高且不预测真实能力。必须在训练前把基准样本从训练集剔除。**

- 方法:n-gram 重叠匹配(训练样本和基准题有长 n-gram 重合就剔除)、embedding 相似度匹配;
- 难点:污染是**结构性**的(模型会看到能找到的一切),不可能 100% 干净,但必须尽力;
- 这直接关系评估可信度(详见《LLM与Agent评估专项手册》第 2 节)。

### 3.1 决策细节与判据:n-gram 重叠阈值定多少

各大模型对"多长的重叠算污染"取值不同,这是最常用的判据:

| 模型/工具 | 污染判据 | 备注 |
|-----------|----------|------|
| GPT-2 | 评测集的 **8-gram(词)**出现在训练集 | 早期发现测试集与 WebText 平均 3.2% 重叠 |
| GPT-3 | **13-gram** 碰撞即剔除 | 实际按数据集在 **8~13** 间取;lm-eval-harness 统一用 13 |
| GPT-4 | **50 字符**子串碰撞 | 改用字符级 |
| Llama-2 | **> 10 个 token** 的 token n-gram 在两侧都出现 | 改用 token 而非词,更稳 |

> **怎么选阈值**:n-gram 越短越敏感(召回高但**多选多choice题误判**——选项排列相似就误判);越长越宽松(漏掉改写)。**默认 13-gram(GPT-3/lm-eval-harness)是稳妥起点**;评测含多选题时注意假阳性。

**n-gram 重叠的致命短板与补强:**

- **只能抓精确匹配**:改写、翻译能轻易绕过——实验显示在改写样本上训练,Llama-2 的 MMLU 能从 45.3 虚高到 88.5;
- **补强方案**:① embedding 相似度检索(召回广但假阳性多);② **LLM 去污染器**(先 embedding 取 top-k 近邻,再让 GPT-4 判是否实质等价)——对"改写型污染"显著优于纯字符串匹配。

> **实操**:优先在训练前从训练集**剔除**;若无法重训,至少检测出被污染的评测样本、产出"干净子集"再报分。

## 4. 数据配比(Data Mixture):配方就是能力

### 4.1 配比决定能力分布

代码/数学/多语种/网页的比例,直接决定模型的能力侧重。拍脑袋定配比是常见错误。

### 4.2 自动搜配比

- **DoReMi**:用一个小代理模型,通过 group DRO 自动学习各 domain 的最优权重,再用到大模型训练;
- **RegMix**:把"数据配比→性能"建模成回归问题,训一批小模型拟合,预测最优配比;
- 共识:**用小规模实验搜配比,别在大 run 上赌**。

### 4.3 课程与分阶段

把数据按训练阶段分层:主体用通用网页,**退火/mid-training 阶段换上高质量 + 推理 + 代码数据**(见《预训练原理与技巧》2.4)。

### 4.4 决策细节与判据:配比与上采样的具体数字

**业界实际配比(可作起点,务必在自己评估集上消融):**

| 模型/阶段 | 通用网页 | 数学/推理 | 代码 | 多语种 | 出处 |
|-----------|---------|-----------|------|--------|------|
| Llama 3.1 主体 | ~50% | ~25% | ~17% | ~8%(覆盖 30+ 语种) | Llama 3 技术报告 |
| SmolLM2 阶段1 | 90% | — | 10% | — | SmolLM2 |
| SmolLM2 阶段3 | 74% | 10% | 16% | — | 后期升代码/数学占比 |
| SmolLM2 退火 | 58% | 14% | 24% | 4% 合成教材 | 留最好数据给最后 |
| MiMo-7B 退火 | — | 数学+代码合计 **~70%** | | — | 末段激进上采样 |

> **配比的两条规律**:① 代码/数学占比**随阶段递增**——主体阶段适中(Llama 3 约 17% 代码、25% 数学),退火/mid-training 阶段大幅拉高(部分模型到 70%);② **把最好的数据留到最后**(退火段),配合学习率退火到 0 + 检查点平均(Polyak)。

**何时上采样高质量域、epoch 上限是多少:**

- **退火段上采样高质量代码/数学**是标准配方(源自 DCLM 和 Llama 3),Llama 3 8B 在 GSM8k/MATH 上分别提升 **24.0% / 6.4%**;
- **epoch 上限 ≈ 4**:Muennighoff et al. 发现**重复超过 4 epoch 后收益急剧递减**,业界因此把单样本重复次数**限制在 ≤4**;
- **上采样的隐患**:DCLM 式过滤会丢掉约 **90%** 原始 token,若再激进上采样小的高质量子集,很容易突破 4 epoch(如 top-10% 子集在 1B-5x 预算下每样本要看 **10 遍**)——这时该放宽过滤阈值(如取 top-20%,每样本降到 5 遍)而非硬上采样。

> **规模依赖的关键判据**:退火/上采样对**小模型(8B)收益大**,对**超大模型(405B)收益可忽略**(其 in-context 推理已够强)。别无脑照搬大模型配方到小模型,反之亦然。配比一律用**小模型实验自动搜(DoReMi/RegMix)**,别在大 run 上赌。

## 5. 后训练数据:指令数据合成

人工写指令-回答对太贵,合成是主流。

### 5.1 Self-Instruct 系:从种子自举

> **Self-Instruct:用少量种子指令,让强模型"生成更多新指令 + 对应回答",自举出大规模指令集。** Alpaca 用它从 175 条种子 + GPT 生成出 52K 指令,开启了开源指令微调潮。

### 5.2 Evol-Instruct:让指令变难变多样

> **WizardLM 的 Evol-Instruct:用 LLM 把简单指令"进化"——加约束、加深度、加推理步、换场景,生成更复杂多样的指令。** 解决 Self-Instruct 指令偏简单的问题。

### 5.3 Magpie:零种子自合成

> **Magpie 的巧思:对齐过的模型只给"对话模板的前缀"(没有任何指令),它会自己"补全"出一个用户指令;再让它回答。完全自动、无需种子,大规模生成高质量指令对。**

### 5.4 蒸馏(distillation)

用强模型(GPT-4/Claude)的输出训小模型——简单有效但有合规/许可风险,且会继承强模型的偏差和错误。

## 6. 数据筛选(Data Selection):少而精

合成出一大堆后,**筛选比生成更关键**——LIMA 证明 1000 条精选 > 海量噪声。

### 6.1 三个筛选维度

| 维度 | 怎么做 |
|------|--------|
| **质量** | 用 reward model / LLM-judge 给样本打分,留高分(如 AlpaGasus 用 GPT 打分筛 Alpaca) |
| **多样性** | 去语义近重复,覆盖任务/难度/领域(嵌入聚类、保证分布广) |
| **影响力** | 选对目标任务"最有用"的样本(LESS 用梯度影响估计) |

### 6.2 代表方法

- **AlpaGasus**:用 LLM 给指令数据打质量分,9K 精选 > 52K 全量;
- **LESS**:基于梯度的影响力估计,选对目标任务最有帮助的子集;
- **DEITA**:综合复杂度 + 质量 + 多样性的评分筛选。

> 实践纪律:**先保证多样性覆盖,再在每类里挑质量最高的**——只挑质量不管多样性会偏科。

### 6.3 决策细节与判据:评分指标、阈值与接受标准

**IFD(Instruction-Following Difficulty)分数——可执行的质量筛选判据:**

- 定义:**loss / 条件 loss 之比**,衡量"指令对生成回答的帮助有多大";
- **高 IFD = 高质量**(指令真正需要被学,多为创作/复杂推理类);**低 IFD** 多为规则跟随、模型本就会的,可删;
- 选"高 IFD 的 cherry data" 重训;
- **效率技巧**:不同大小模型算出的 IFD 高度一致,可用 **GPT-2 这种小模型**来打分,极快且省。

**固定阈值的坑与改进:**

- 固定阈值卡分会**被表层词汇特征骗**(高分来自措辞而非真质量);
- 改进:**邻域感知**(T-Shirt:偏好"邻居 S-IFD 均值高、方差低"的样本)而非裸卡阈值。

**LLM-as-judge 作接受门的标准(合成数据筛选):**

- 给判官**显式 rubric**(准确性、有用性、指令遵循、真实性、安全性)+ 打分格式(pairwise / 数值 / pass-fail);
- 典型做法是**拒绝采样**:一个 prompt 采多个候选,judge 挑最优(UltraFeedback 即此范式,可同时产出 RM 训练信号);
- **必须控偏置**:位置偏置(双向打分、只计一致胜出)、冗长偏置、自我增强偏置(**用不同模型家族当judge**)。IFD 原作也用"双序送judge"消位置偏置。

> **何时该上 LLM 评分过滤**:启发式(长度、去重、毒性)是廉价第一道闸;要分"普通 vs 优秀"才上 IFD / RM / LLM-judge。注意 judge 会**放大教师模型的系统偏差**,且合成数据可能与真实用户分布不匹配——别只看合成基准。

**没有单一指标通吃**:Alpaca-Eval 2.0 上 IFD 优于 DEITA,但 BBH 上 DEITA 反超 IFD——按目标任务选指标。

---

## 7. 偏好数据:对齐的燃料

(用于 DPO/PPO/GRPO,见《PPO-GRPO-DPO训练技巧》)

- **构造**:同一 prompt 采多个回答,用人工或 reward model / LLM-judge 标"哪个更好"(chosen/rejected);
- **质量 > 数量**:噪声偏好对会直接教坏模型(DPO 对噪声标签敏感);
- **覆盖难度梯度**:chosen 和 rejected 的差距要有区分度——差距太小学不到,太大没信息量;
- **on-policy 更好**:用当前模型自己生成的回答构造偏好对(而非别的模型),分布更匹配(iterative/online DPO)。

## 8. 常见坑汇总(速查)

| 坑 | 说明 | 对策 |
|----|------|------|
| 只堆数据量 | 噪声拖垮质量 | 多级过滤,质量优先 |
| 不去重 | 模型死记、浪费算力 | MinHash 近似去重 |
| 不去污染 | 评测分虚高 | n-gram/embedding 剔除基准 |
| 过度过滤/去重 | 数据量塌、覆盖丢 | 平衡;低质数据改写回收 |
| 拍脑袋定配比 | 能力偏科 | DoReMi/RegMix 自动搜 |
| 合成数据照单全收 | 含噪声 | 质量+多样性+影响力筛选 |
| 只挑高质量 | 偏科、多样性差 | 先保多样性再挑质量 |
| 偏好对有噪声 | 教坏对齐 | 严控标注质量,差距适中 |
| 蒸馏不看许可 | 合规风险 | 确认数据/模型许可 |
| 后训练堆量 | 边际收益低还可能变差 | 少而精(LIMA 启示) |
| 去污染只用 n-gram | 改写/翻译型污染漏网(MMLU 可虚高到 88.5) | 补 embedding + LLM 去污染器 |
| 激进过滤伤长程训练 | 丢 90% token,小子集被迫超 4 epoch | 长程放宽阈值/改写回收;重复 ≤4 epoch |
| 裸卡固定质量阈值 | 被表层词汇骗、选到伪高分 | 邻域感知选择;控 judge 偏置(双序、跨家族) |
| 照搬大模型配比到小模型 | 退火上采样收益随规模反向 | 小模型实验单独搜配比 |

## 9. 推荐实操流程(端到端)

**预训练数据:**
1. 采集(Common Crawl/领域语料)→ 文本提取 → 语言过滤;
2. 规则过滤(启发式)+ 模型质量过滤(分类器,针对目标能力定制);
3. MinHash 去重 + 评测基准去污染 + PII 处理;
4. DoReMi/RegMix 搜 domain 配比;分阶段课程(退火喂高质量)。

**后训练数据:**
5. 指令合成:Self-Instruct/Evol-Instruct/Magpie 起量,或精标种子;
6. 筛选:质量(LLM-judge 打分)+ 多样性(去重覆盖)+ 影响力(LESS),少而精;
7. 偏好数据:同 prompt 多回答 + 标注 chosen/rejected,控噪声、保区分度,优先 on-policy;
8. 全程对照评估集做消融,别信通用配方。

---

## 10. 一句话总结

数据工程的精髓:**模型上限即数据上限——预训练靠"大规模多级过滤 + 去重去污染"在噪声里捞高质量(质量过滤是最大单点杠杆),后训练靠"合成起量 + 质量/多样性/影响力三维筛选"做到少而精(1000 条精选胜过万条噪声);配比用小模型实验自动搜而非拍脑袋。** 最大的杠杆是**过滤/筛选的质量**,最大的陷阱是**只看数量**和**训练集混进评测题**。
