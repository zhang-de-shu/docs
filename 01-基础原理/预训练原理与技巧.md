> 面向工程师的 LLM 预训练实战手册。讲清楚从零训一个 base 模型时,**算力怎么分配、数据怎么配、学习率怎么调度、loss 尖峰怎么救、怎么从小模型外推大模型**——以及为什么这些技巧是"省钱"而非"炫技"。

## 0. 全景:预训练的第一性原则

预训练本质是一场**固定预算下的资源分配博弈**:给定算力 C(FLOPs),你要决定模型多大(参数 N)、数据喂多少(token D),并保证训练别崩。围绕这个目标有四个核心矛盾:

| 矛盾 | 解法 | 作用 |
|------|------|------|
| 算力有限,N 大了 D 就小,怎么分 | **Chinchilla 缩放律(N:D ≈ 1:20)** | 在固定 C 下逼近最优 loss |
| 训练后期推理成本 vs 训练成本 | **过训(over-train)小模型** | 牺牲训练最优换推理省钱 |
| 大模型一次训太贵,调参试不起 | **μP + 缩放律外推** | 小模型调好超参,零成本迁移到大模型 |
| 训着训着 loss 突然爆炸 | **梯度裁剪 + WSD 调度 + 数值稳定** | 防止 loss spike 毁掉整个 run |

> **核心矛盾**:预训练最贵的不是"训不出来",而是"训到一半崩了"或"算力分配错了"。一次 100B+ 模型的训练动辄数百万美元,**任何系统性浪费都不可接受**。全文都在围绕"如何用最少 FLOPs 拿到最低 loss、且不中途翻车"展开。

## 1. 缩放律(Scaling Laws):算力该怎么分

### 1.1 Kaplan vs Chinchilla:历史性的修正

- **Kaplan et al.(2020,OpenAI)**:最早系统化 loss 随 N/D/C 的幂律下降,但结论偏向"模型越大越好",导致 GPT-3 这类**严重欠训**(参数大、数据少)。
- **Chinchilla(2022,DeepMind)**:修正了 Kaplan 的学习率调度缺陷,得出**计算最优配比**:

> **给定算力,参数 N 与训练 token D 应当同比例增长——经验值约 D ≈ 20 × N(每个参数配 ~20 个 token)。** 70B 模型的计算最优数据量约 1.4T token。

关键启示:Chinchilla 之前的大模型(GPT-3 175B 只训 300B token)都"训不够",同算力下一个更小但喂更多数据的模型反而更强(Chinchilla 70B 打败 Gopher 280B)。

> **判据(TPP = token/参数比):** TPP < 20 是**算力浪费区**——Chinchilla 与后续复现都确认低于 20 的训练单位 FLOPs 收益更差,除非你有特殊推理约束,否则**不要让 TPP 低于 20**。TPP ≈ 20 是训练 FLOPs 最优点;TPP > 20 进入"过训区",见下节。Epoch AI 2024 的复现修正了原论文的内部不一致(数据缩放指数 β、不可约 loss E 偏低),但**结论仍落在 ~20 token/参数**这一量级。

### 1.2 计算最优 ≠ 部署最优:故意"过训"

Chinchilla 给的是**训练 FLOPs 最优**,但它忽略了**推理成本**:

> **如果模型要被海量调用,把一个更小的模型喂远超 20×N 的数据(over-training),训练时多花钱,但推理时永远省钱。** LLaMA / Qwen / 现代开源模型普遍训到 15–20T token(远超 Chinchilla 最优),就是这个逻辑。

- LLaMA-2 训了 2T token,**LLaMA-3 8B 训了 15T token**(约 1875 token/参数,~75× Chinchilla);LLaMA-3 70B 约 **200 token/参数**(~10× Chinchilla);Phi-3 更极端,约 **870 token/参数**(~45× Chinchilla)。
- 代价:训练时收益递减(loss 下降变慢),但换来一个又小又强、推理便宜的模型。

**什么时候该过训(可执行判据)——看推理需求量:**

| 信号 | 选 compute-optimal(TPP≈20) | 选 inference-optimal(过训) |
|------|------|------|
| 预期推理调用量 | 小(科研、一次性评估) | 大(产品级,~1B+ 请求或 ~万亿 token 推理) |
| 优化目标 | 单次训练 FLOPs 最小 | 全生命周期(训练+推理)总成本最小 |
| 典型 TPP | 20 | 100–1000+ |

> **量化判据(Sardana et al. 2024,"Beyond Chinchilla-Optimal"):** 预期推理量大(~10 亿请求级)时,应训得**比 Chinchilla 更小、更久**。一个例子:要训 13B 模型且预期生命周期推理量 2T token,**改训 7B 并多喂数据,总算力可省 ~17%**。同文还发现一个关键事实:**TPP ≥ 20 时各 TPP 的"每 FLOP 降 loss 效率"几乎平行**——也就是说过训不会让单位算力效率明显变差,只是收益递减;真正低效的是 TPP < 20。
>
> **何时停止过训:** 当参数量压到等效 Chinchilla 模型的 ~20% 以下时开始触及渐近线(LLaMA-3 8B 量级),再压参数收益急剧衰减——这是"过训到什么程度"的经验上界。

### 1.3 数据受限时的缩放(data-constrained)

当高质量数据不够 20×N 时怎么办?

- **重复 epoch 是有损但可行的**:研究(Muennighoff et al.)发现**最多重复约 4 个 epoch**收益接近新数据,之后急剧衰减,16 epoch 后几乎无用。
- 数据墙(data wall)是真实的:互联网高质量文本有限,**合成数据 + 多 epoch + 质量过滤**成为主流应对(见《数据工程手册》)。

## 2. 学习率调度:WSD 取代 Cosine

### 2.1 经典:Warmup + Cosine Decay

长期标准是 **warmup(线性升到峰值)→ cosine 衰减到峰值的 ~10%**。问题:

- cosine 必须**预先知道总步数**——中途想加训、想改数据配比就得重来;
- 没法"在任意点拿到一个好 checkpoint"——曲线中段的 ckpt 都不是最优。

> **澄清两个"10%"(常被混淆):** ①**衰减终点 lr** = 峰值的 10%(cosine 的传统终点);②**衰减阶段时长** = 总步数的某个比例(WSD 的 Decay 段)。二者是不同的旋钮,下文分别给判据。

### 2.1.5 谁在用 cosine,谁在用 WSD(选型判据)

| 场景 | 选 cosine | 选 WSD |
|------|------|------|
| 总步数是否预先固定 | 是(一次性 run,不续训) | 否(要续训/多尺度切 ckpt) |
| 是否要在训练中途换数据/退火 | 不需要 | 需要(Stable 段任意切出去 Decay) |
| 是否要用同一条 Stable 跑缩放实验 | 不方便 | 方便(MiniCPM 即用 WSD 测出 data/model 最优比) |
| 现代实践 | 仍是稳妥默认 | 新主流(MiniCPM/DeepSeek-V2/Llama-3.1 谱系) |

### 2.2 新主流:WSD(Warmup-Stable-Decay)

MiniCPM / DeepSeek 推动的 **WSD**(也叫 trapezoid / WSD)三段式:

> **Warmup 升到峰值 → 长时间恒定峰值 lr(Stable)→ 最后一小段急速衰减(Decay)。**

优势(为什么取代 cosine):
- **可在 Stable 段任意点切出去做 Decay** = 一次训练得到多个规模的模型,不必预设总步数;
- Decay 段 loss 会**断崖式下降**——出现一个戏剧性的"loss 悬崖",这是 WSD 的标志现象;
- 便于续训:Stable 段是"存档点",随时可加数据继续。

**各阶段比例(可执行取值):**

| 阶段 | 经验比例 | 判据/来源 |
|------|------|------|
| Warmup | 总步数的 ~1–2%(长 run);小模型缩放实验可到 10–25% | 步数越多 warmup 占比越小;CBS 缩放实验在 85–151M 上扫出 **0.25 最优**(见 §6.x batch/warmup) |
| Stable | 总步数的 ~60–80% | 主体训练,高 lr 沿"河谷"快速前进 |
| Decay | 总步数的 **~10–20%** | MiniCPM/River-Valley 偏 **~10%**;Hägele et al. 偏 **~20%**;两者都落在稳健的 10–25% 区间 |

> **Decay 段长度判据:** River-Valley 的消融显示**只要 Decay 占比在 ~10% 附近、且不要开始得太早,最终性能对精确比例并不敏感**;CNN 等非 Transformer 任务需要更长(~35%)才追平 cosine。工程上**先用 10%,要追极致再试 20%**。
>
> **Decay 终点判据(decay-to-zero):** 传统做法衰减到峰值 10%(GPT-3/Gopher/Chinchilla/Llama/Llama2 全是此默认)。但 Cerebras 2025"Straight to Zero"证明:在各自最优峰值 lr 下,**线性衰减到 0(D2Z)在 compute-optimal TPP 上一致优于衰减到 10%,且 TPP 越高 D2Z 的优势越大**。极端例子:617M 模型用 D2Z 训 80 TPP 的 loss 低于用 10× 衰减训 200 TPP——**省 ~60% FLOPs**。推论:Llama2-7B(286 TPP + 10× 衰减)是"欠衰减"的。**判据:高 TPP / 过训场景优先 D2Z(线性略优于 cosine 形状);D2Z 的最优峰值 lr 还更稳定,不像 10× 衰减那样随 TPP 升高被迫显著调低。**

### 2.3 "河谷(river-valley)"损失景观直觉

WSD 之所以有效的理论解释:loss landscape 像一条**深河谷**——Stable 段高 lr 让模型沿河谷快速"漂流"(沿谷底前进但在两壁间震荡),Decay 段降 lr 让模型"沉到谷底"(收敛到河床最低点)。高 lr 探索 + 低 lr 收敛的分工。

### 2.4 退火(annealing)= 把好数据留到最后

Decay 段的另一个用法:**在退火阶段换上最高质量的数据**(教科书、精选代码、合成推理数据)。因为此时 lr 在快速下降、模型在"定型",喂高质量数据的边际收益最大。这就是 **mid-training / annealing** 的核心思想——把数据配比按训练阶段分层。

## 3. 训练稳定性:loss spike 的防治

大规模训练最怕**loss 突然飙升**(spike),轻则拖慢、重则毁掉整个 run。

### 3.1 spike 从哪来

- **梯度爆炸**:某个 batch 触发极大梯度,一步把权重推到坏区域;
- **数值溢出**:低精度(FP16/BF16/FP8)下激活或梯度超出表示范围(FP16 上限 65504,梯度在 unscale 前超过即溢出);
- **注意力 logits 爆炸**:attention 分数过大,softmax 饱和(QK 内积无界);
- **浅层/线性层输出范数无界增长**:高 lr 下 QKV、Proj、FC2 等线性层输出 L2 范数逐步增长,发散时这些层范数比收敛模型**大 >2×**——这是机理性的早期信号;
- **Adam 的链式反应**:某参数更新偶发达到极大值,叠加高 lr 后大幅偏离轨道,通过连接传播给邻接参数,触发连锁 spike;
- **数据触发**:出现 spike 的 batch 里**高频含长重复 n-gram 序列**——OLMo 2 直接过滤重复 n-gram 来防 spike;
- **小初始化 + 强 weight decay 的交互**:embedding 被 weight decay 压得过小,而 layer_norm(x) 对 x 的 Jacobian 与 ∥x∥ 成反比,导致浅层梯度被放大(Takase et al. 2024)。

> **良性 vs 恶性 spike:** 良性 spike 会自行恢复;恶性 spike 不可逆地发散(常以 NaN/Inf 收场)。一个反直觉事实:**重放触发 spike 的同一个 batch 往往无法稳定复现**——所以"跳过该 batch"是经验补救而非根因修复。

### 3.1.5 检测信号(在 loss 飙之前就报警)

> **核心:grad norm 与各层激活/输出范数的异常往往先于 loss spike 出现。** 监控这些代理量,把"等 loss 爆"变成"提前拦截"。

- **grad norm 的统计异常**:对历史 grad norm 取 EMA + 标准差,当前步 **z-score 超阈值**即视为异常(ZClip 思路,典型 warmup 25 步先估均值/方差);
- **线性层输出 L2 范数 >2× 收敛基线**:QKV/Proj/FC2 的范数监控;
- **NaN/Inf 检测**:单次偶发可恢复,**频繁出现**=系统性问题(lr 过高或配置不稳);
- **loss scaler 异常**:FP16 下 loss scale 变 0 或 NaN(连续下溢后又溢出)。

### 3.2 经典防线(附触发/取值判据)

- **全局梯度裁剪**:`max_grad_norm=1.0` 是基线;**不稳时降到 0.3**(OLMo 实践把 1.0→0.3 配合剔除问题数据);
- **bf16 优于 fp16**:bf16 动态范围大(8 位指数),溢出风险远低于 fp16,现代预训练默认 bf16;
- **z-loss**:对 softmax 的 normalizer 加正则项 `1e-4 · log²Z`(PaLM/OLMo 2 取此系数),防 logits 漂移;
- **QK-norm**:对 Q、K 做 RMSNorm 再算注意力,直接掐住 logits 爆炸的源头——**注意副作用:它剥离了 query-key 点积的幅度,会损伤长上下文任务**(RNoPE 发现),长上下文模型需权衡;
- **logit softcapping(Gemma 式)**:对 attention / LM-head logits 软上限;**QK-norm + softcap 组合可把可用 lr 提高 1.5× 而不发散**;
- **reorder-norm + QK-norm 协同(OLMo 2)**:把 norm 放到 attention/FFN 输出后(Post-Norm 风味,但仍在残差内)+ QK-norm,**单用任一个都没用,合用才同时压住梯度范数的增长与尖峰**;
- **AdamW ε = 1e-8**:OLMo 2 发现把 ε 设为 1e-8 能**降低并稳定训练早期的 grad norm**,loss 也降得更快;
- **embedding 不加 weight decay** + 初始化 std=0.02:防止 embedding 被压过小引发浅层大梯度。

### 3.2.5 出事之后:跳过 batch 与回滚(触发条件)

> **触发条件:** 检测到恶性 spike(loss 持续上升 / NaN-Inf 频发 / grad norm z-score 持续异常)→ 执行回滚。
>
> **标准操作(经验值):** 从 spike 起点**前 ~100 步**的 checkpoint 恢复,并**跳过约 200–500 个 batch**(PaLM 540B 全程 >20 次 spike 即如此处理;65B 模型曾为此多花 30 天 / 129.3 MWh)。
>
> **SPAM 式更精细的做法:** 检测到大梯度 spike 时**重置 Adam 的一阶/二阶矩**(清动量),并只对"尖峰梯度"做缩放(而非裁掉所有梯度),尽量保留有用信号。

### 3.3 新一代自适应裁剪(2025–2026)

- **AdaGC**:自适应梯度裁剪,按参数/历史动态定阈值,比固定阈值更稳;
- **ZClip**:基于梯度范数的 z-score 异常检测,只在"统计异常"时裁剪,不误伤正常大梯度——**触发条件:当前 grad norm 相对历史 EMA 的 z-score 超阈值**(典型先用 ~25 步 warmup 估均值/方差,裁剪后用裁剪值更新统计);
- **MuonClip(Kimi K2)**:针对 Muon 优化器的注意力 logit 爆炸,通过 **qk-clip** 缩放 Q/K 权重,使 Kimi K2 在万亿参数训练中**零 loss spike**。

> 趋势:从"固定阈值一刀切"转向"统计自适应",在不牺牲收敛的前提下精准拦截异常步。固定阈值的问题是**要么误伤正常大梯度、要么漏拦真正的异常**;自适应裁剪用历史分布定"什么叫异常"。

## 4. 超参外推:μP 让大模型零成本调参

### 4.1 痛点:大模型调不起参

100B 模型训一次几百万刀,**不可能 grid search 学习率**。但小模型的最优 lr 直接搬到大模型上往往不对。

### 4.2 μP(Maximal Update Parametrization)

> **μP 重新参数化初始化方差与各层学习率,使得"最优超参在不同宽度下保持不变"。于是可以在小模型(如 40M)上调好 lr,直接零成本迁移到大模型(如 6B+)。**

这叫 **μTransfer**——在小代理模型上做超参搜索,迁移到目标大模型,省掉天价调参。GPT-4 据传用了类似技术。代价:需要正确实现 μP 的各层缩放规则(初始化、lr、attention scale),实现不对会静默失效。

### 4.2.5 何时用 μP(选型判据)

> **该用 μP 的信号:** ①要把模型**变宽**(hidden size 增大)且不想在大模型上重扫 lr;②要**拟合缩放律**做外推(μP 模型的缩放律拟合更紧,因为各尺度训练动力学一致);③目标模型贵到**只能训一次**。注意 μTransfer 对任意规模都成立,不限于十亿参数级。

**实现验证:coord check(坐标检查)——上大 run 前的第一道、最便宜的关卡:**

- **做法:** 训不同宽度的模型各 ~10 步,记录每类层激活的平均幅度;
- **判据(是否实现正确):** μP 下**各宽度的激活幅度曲线应保持水平(与宽度无关)**;若像 SP 那样随宽度爆炸,则实现错误;
- **关键技巧:** coord check 要**用比正式训练更大的 lr**,否则小 lr 会被初始化掩盖、暴露不出爆炸问题;
- **第二诊断:** 若"越宽训练 loss 反而越差"(超过某宽度后),也是 μP 实现有问题的信号。

**代理模型怎么选(EleutherAI/Cerebras 实操指南):**

| 维度 | 推荐 | 理由 |
|------|------|------|
| 宽度 | hidden ≈ 256 | 够大以让大数定律/中心极限收敛 |
| 深度 | 与目标模型**大致相同** | 深度会移动最优 HP,原始 μP 是"宽度理论",深度需对齐 |
| 训练时长 | 20 token/参数 | 跟 Chinchilla 对齐 |
| 搜索的 HP | base init std、base lr、embedding multiplier、output logit multiplier 四个 | 指南给定的标准四元组 |

> **μP 的边界(2024–2025 重要修正):** 原始 μP 只解决**宽度**迁移。**深度**靠 Depth-μP / CompleteP 扩展;而**开箱 μP 不能跨 token horizon(训练时长)迁移、也不能跨 batch size 迁移**——若代理模型用的 batch size 小于 critical batch size,迁到大模型(在 CBS 或以上)会出问题。跨这些轴需用更新的参数化(CompleteP、Complete(d) Parameterisation);**u-μP**(unit-scaled μP)还把 μP 与单位缩放结合,带来更简单的 HP 与 **FP8 下的低精度鲁棒性**。

### 4.3 缩放律外推

配套手段:训一系列小模型(不同 N/D),拟合 loss 幂律曲线,**外推预测目标大模型的 loss 与最优配比**,先在小规模验证数据配比/架构选择,再放大。这是现代预训练"先做缩放实验、再开大 run"的标准流程。

## 5. 低精度训练:FP8 的工程

### 5.1 为什么要 FP8

BF16 已是标配,但 **FP8** 能再省一半显存/带宽、提速近 2×。难点:FP8 只有 ~2–3 位有效精度,极易溢出/下溢。

> **何时上 FP8(选型判据):** ①规模大到带宽/显存成为瓶颈、且追求 ~2× 吞吐;②有 Hopper/Blackwell 级硬件(Blackwell 的 MXFP8 微缩放是硬件原生,反量化开销远低于 Hopper);③你能接受/实现"细粒度缩放 + 关键路径保高精度"这套工程——**FP8 不是一键开关**。DeepSeek-V3 是首个全程 FP8 训练的开源大模型,相对 BF16 精度损失 **<0.25%**,代价是整套数值工程。验收判据就是这个 **<0.25% 相对 BF16** 的 loss 差。

两种格式:
- **E4M3**(4 位指数 3 位尾数):精度高、范围小,用于**前向激活/权重**;
- **E5M2**(5 位指数 2 位尾数):范围大、精度低,用于**反向梯度**。

> **格式选择判据:**
> - **每张量缩放(per-tensor)** 下用**混合配方**:前向 E4M3(值聚集、精度优先),反向 E5M2(梯度跨多个数量级、范围优先);
> - **细粒度块缩放(block/tile,如 DeepSeek-V3 或 MXFP8)** 下**全程 E4M3**——每块独立 scale 等于在小组内共享指数位,补回了动态范围,反而**不该再用 E5M2**(8B 模型上对梯度用 E5M2 会让 perplexity 变差)。

### 5.2 DeepSeek-V3 的细粒度缩放

> **DeepSeek-V3 不对整张张量用一个缩放因子,而是 tile/block 级细粒度缩放(activation 按 1×128、weight 按 128×128 分块各自定 scale),把高精度累加放在 CUDA core 上。** 这样既享受 FP8 的速度,又把溢出风险控制在小块内。

关键技巧:**关键路径保高精度**(优化器状态、master weights、部分累加用 FP32/BF16),只在 GEMM 的输入用 FP8。FP8 不是全程 FP8,而是"该省的省、该保的保"。

> **哪些必须保高精度(数值稳定性判据):**
> - **master weights、weight gradients、优化器状态** → BF16/FP32(否则小更新被舍入成 0,梯度/动量里的小值也存不住);
> - **敏感模块保原精度** → DeepSeek-V3 对 **embedding、output head、MoE gating、normalization、attention 算子**保 BF16/FP32;Transformer Engine 也建议 **最后几层**跑更高精度(对量化最敏感);
> - **累加精度** → FP8 GEMM 在 Hopper Tensor Core 上累加只有 ~14 位有效(K=4096 时相对误差可逼近 2%),必须**提升到 CUDA Core 用 FP32 累加**,GEMM 输出 BF16/FP32。

> **per-tensor delayed vs block 在线缩放(选型):**
> - **delayed scaling(用历史 amax 定 scale)**:吞吐最高,但要存 amax 历史、且对离群值不稳;
> - **online/block scaling(DeepSeek-V3,逐 1×128 tile / 128×128 block 在线算 amax)**:抗离群值、**分布式下无需跨节点同步 scale**(每块 scale 本地),代价是反量化开销——在 Blackwell 微缩放上很便宜。
> - **判据:** 张量内动态范围大(有离群值)→ 选块缩放;追极致吞吐且分布稳 → delayed。

## 5.5 batch size 与 warmup:具体取值与判据

这两个旋钮看似简单,却直接决定"并行效率"和"早期会不会崩"。

### 5.5.1 critical batch size(CBS):并行的天花板

> **定义:** CBS 是"再加大 batch 就开始边际递减"的阈值。**低于 CBS**,batch 翻倍可近似线性减少达到目标 loss 所需的步数;**高于 CBS**,继续加大 batch 只是浪费算力(步数不再成比例下降)。

**关键判据(How Does CBS Scale,2024 + Power Lines,2025):**

- **CBS 主要随数据量增长,而非模型大小**——这修正了早期"CBS 由 compute/loss 决定"的看法。意味着**训练越往后、见过的数据越多,可用的 batch 越大**。
- 实操推论:**batch size warmup(逐步加大 batch)** 比一开始就用大 batch 更高效。OLMo 1B 的做法:初始 batch=1024,据 CBS 测量在 **168B token 时翻到 2048、503B token 时翻到 4096**,最终用 **少 43% 的梯度步**达到同等(略更好)loss。
- **怎么提前知道 CBS:** 传统用 gradient noise scale 作代理(GPT-3 即用),但 Allen AI 发现该代理在 OLMo 上不可靠,改用直接测量。**判据:noise scale 越大(样本间梯度差异越大)→ 可用 batch 越大。**

**典型 batch size(token 计):** Llama-3 70B ≈ 4M token/步;Llama-3 旗舰(405B,16K GPU)≈ 16M token/步。

### 5.5.2 warmup:取值与判据

| 场景 | warmup 取值 | 来源/判据 |
|------|------|------|
| 长 run(总步数 >100k) | 固定 300–3000 步,或总步数 1–2% | Scaling-Beyond-Fixed-Durations:多数 run 300 步,长 run 1000–3000 |
| 小模型缩放实验(85–151M) | 总步数 **~25%** | CBS 论文扫 {0.15,0.25,0.35},**0.25 一致优于 0.15、仅略逊 0.35** |
| Power Lines 设定 | 10% warmup + decay-to-zero | μP HP 来自小代理模型 |
| 微调(对比) | 总步数 6–10% | 总步数小得多,占比自然更高 |

> **warmup 的作用机理(为什么不能省/不能太快):** lr 升太快或起点太高,会在激活范数、optimizer moment 尚未稳定前就施加大更新,**过冲进 loss landscape 的尖锐区**——直接触发梯度范数爆炸、FP16 溢出跳步、或 loss 大幅震荡。warmup 给这些统计量"预热"的时间。

## 6. 数据配比与课程(curriculum)

(数据采集/清洗见《数据工程手册》,这里只讲与训练调度耦合的部分)

1. **领域配比影响泛化**:代码/数学/多语种的比例直接决定能力分布。**DoReMi / RegMix** 用小代理模型自动搜索最优 domain 权重,而非拍脑袋。
2. **课程学习**:从易到难、从通用到专精。常见做法是**预训练主体用通用网页,退火阶段加高质量/推理数据**(见 2.4)。
3. **去污染(decontamination)**:训练集必须剔除评测基准的样本,否则分数虚高(见《评估专项手册》)。
4. **长上下文是后期扩展**:多数模型先在 4K–8K 上训主体,**后期用少量长样本 + RoPE 频率调整(如 YaRN)扩到 128K+**,而非全程长序列(太贵)。

---

## 7. 评估:别只看 training loss

1. **盯验证 loss / 困惑度(perplexity)**,但它只是代理指标;
2. **下游任务零样本/少样本评估**:MMLU、GSM8K 等能力基准定期跑(注意污染);
3. **emergent 能力非线性**:某些能力到一定规模才"涌现",小模型测不出,别因小模型不会就否定方向;
4. **训练动力学监控**:grad norm、loss 平滑度、各层激活范数——异常往往先于 loss spike 出现。

## 8. 常见坑汇总(速查)

| 坑 | 说明 | 对策 |
|----|------|------|
| 按 Kaplan 配比 | 模型大、数据少,严重欠训 | 用 Chinchilla(~20 token/参数)起步 |
| TPP < 20 | 单位算力收益更差 | 至少 TPP≈20;部署量大再过训 |
| 死守计算最优 | 推理成本高 | 推理量大(~1B+ 请求)就过训小模型 |
| cosine 锁死总步数 | 没法续训/多尺度 | 用 WSD,Stable 段可任意切 |
| 衰减只到峰值 10% | 高 TPP 下"欠衰减",loss 偏高 | 高 TPP 用 decay-to-zero(线性 D2Z) |
| Decay 段开始太早 | WSD 优势打折 | Decay 占比 ~10–20% 且别太早起 |
| 高质量数据全程平铺 | 边际收益浪费 | 退火阶段集中喂高质量数据 |
| 固定阈值梯度裁剪 | 误伤或漏拦 | AdaGC/ZClip 自适应裁剪(z-score) |
| 只在 loss 爆后才反应 | 已浪费算力 | 监控 grad norm / 层输出范数,提前拦截 |
| QK-norm 无脑全用 | 损伤长上下文 | 长上下文场景权衡,可配 softcap |
| 大模型直接调参 | 烧钱且不对 | μP + μTransfer 小迁大,先 coord check |
| μP 跨 batch/时长迁移 | 开箱 μP 不支持,静默失效 | CompleteP/Complete(d);代理 batch ≥ 起不超 CBS |
| FP8 全程低精度 | loss 崩 | 细粒度缩放 + 关键路径(master/优化器/敏感层)保高精度 |
| FP8 块缩放还用 E5M2 | perplexity 变差 | 块缩放下全程 E4M3 |
| 一开始就用大 batch | 早期超过 CBS,浪费 | batch size warmup,随数据量翻倍 |
| 拍脑袋定 domain 配比 | 泛化次优 | DoReMi/RegMix 自动搜权重 |
| 训练集含评测题 | 分数虚高 | 严格去污染 |
| 只看 training loss | 看不到真实能力 | 下游基准 + 训练动力学监控 |

## 9. 推荐实操流程(端到端)

1. **定预算**:有多少 GPU·小时 → 算出 FLOPs 预算 C。
2. **缩放实验**:训一组小模型,拟合 loss 幂律,定 N/D 配比(TPP≈20 起步,推理量大则过训到 TPP 100–1000)。
3. **μP 调参**:小代理模型(hidden≈256、深度对齐目标)上搜 lr/init,**先 coord check 验证实现**,再 μTransfer 到目标规模。
4. **数据管线**:质量过滤 + 去污染 + DoReMi 定 domain 权重 + 过滤重复 n-gram(见《数据工程手册》)。
5. **稳态训练**:bf16/FP8、WSD 调度、warmup(长 run 1–2% 步数)、batch size warmup(随数据量翻倍)、梯度裁剪 + 自适应 spike 防护(z-score),实时监控 grad norm 与层输出范数。
6. **退火**:最后 10–20% 段降 lr(高 TPP 用 D2Z),换高质量 + 推理数据;按需做长上下文扩展。
7. **评估**:验证 loss + 下游基准(去污染),按真实能力而非 loss 选 ckpt。
8. **接后训练** → SFT → 偏好/RL(见本仓库对应文档)。

---

## 10. 一句话总结

预训练的精髓:**在固定算力下,用缩放律把参数与数据配到最优(部署量大就故意过训),用 μP 把超参从小模型零成本迁到大模型,用 WSD 调度 + 退火把高质量数据的价值压榨到最后,并用梯度裁剪与 FP8 细粒度缩放守住数值稳定不让 loss 崩。** 最大的杠杆是**算力分配的正确性**与**训练不中途翻车**——而 training loss 曲线漂亮不代表这两件事做对了。
