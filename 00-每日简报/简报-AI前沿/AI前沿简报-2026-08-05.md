## 基座模型与开源大模型

- **Qwen3.8-Max（阿里，8月3日发布，权重下周开源）**
  - 简介：阿里新一代旗舰基座，总参数 2.4T、激活 95B 的稀疏 MoE，1M 上下文、原生视觉理解；是 Qwen-Max 级别首次开放权重（连 Qwen3.8-27B 一并开源），API 已上线千问平台。
  - 技术原理：基于 Qwen3.5 架构扩展，稀疏 MoE + 混合注意力（少数层全局、多数层局部窗口）联合优化，用总参数换知识容量、用低激活控推理成本。发布重点不在跑分而在三例长程自主交付：16 天无人干预跑出 oh-my-cli 自进化 harness（265 commits/127 PR/151 issues）；125 小时复现《Unified Data Selection for LLM Reasoning》并在 AIME24 上比原方法再高 2.7 分；24 小时内独立完成 WWW2025 多模态对话意图识别赛、击败 87% 人类团队。能力来自"真实环境 + 算力"联合 RL 扩展：解耦可执行环境（Task/Workspace/Harness 三轴组合增长）、统一奖励系统（执行验证 + 评分卡判定 + 智能体审查）、在线数据 balancer 抑制批间梯度方差以支撑 RL 持续 scale。
  - 链接：[官方发布博客](https://qwen.ai/blog?id=qwen3.8) ｜ [自主编程轨迹仓库 oh-my-cli](https://github.com/qwen-code-dev-bot/oh-my-cli)

- **DeepSeek-V4-Flash 正式版 API（7月31日公测）**
  - 简介：DeepSeek-V4 系列的轻量版，284B 总参 / 13B 激活 MoE，1M 上下文；4 月预览版后的首次重大升级，官方称多项基准远超预览版、Agent 能力提升约一个数量级。
  - 技术原理：架构与预览版一致，能力跃升主要归因后训练（两阶段：SFT + GRPO 强化学习先培养领域专家，再 on-policy 蒸馏统一整合）。同系列 V4-Pro 为 1.6T/49B。关键技术：混合注意力 CSA/HCA（百万 token 下单 token 推理 FLOPs 仅 V3.2 的 27%、KV cache 仅 10%）、mHC 增强残差信号传播、Muon 优化器，预训练 32T+ tokens。
  - 链接：[技术报告 arXiv:2606.19348](https://arxiv.org/abs/2606.19348) ｜ [ModelScope 权重](https://modelscope.cn/models/unsloth/DeepSeek-V4-Flash)

## 推理 / 长上下文 / 长程 Agent

- **OpenAI Astra 十项数学新结果（8月1日，含 Lean 证明）**
  - 简介：OpenAI 以 249 页论文 + 62 页发现过程说明 + 一套 Lean 4 形式化证明，公布其"下一代主要模型"Astra 在纯数学与理论计算机科学的十项开放问题上的新结果，覆盖高维几何、编码理论、群论、算术电路复杂度、量子复杂度、格密码、极值组合等。Astra 本身未对外开放，但成果与证明是一手公开的。
  - 技术原理：十项里最突出的是构造了无限有限呈现的非 sofic 群，否定 Gromov 1999 年"所有可数群皆 sofic"猜想（被多位数学家评为"比 5 月证伪 Erdős 单位距离猜想更重要"）；另给 Connes 刚性猜想反例、压低高维球堆积渐近上界、解决三个 Erdős 悬赏问题。每个证明均附 Lean 4 证书（sorry_count=0，仅用 propext/Classical.choice/Quot.sound 三公理），可在本地重跑核验。生成解法消耗 token 按 Sol API 价格折算约 2000 美元（仅 token 成本）。关键范式信号：这是"结果 + 机器可验证证明 + 推理过程重建"的组合，正面回应"无法检验的证明只是声明"这一 AI 数学核心质疑；但形式化只保证推导正确，猜想→命题的翻译是否走样、结果分量仍需人工同行评审。
  - 链接：[OpenAI 官方页面](https://openai.com/index/ten-advances-in-mathematics/) ｜ [249 页论文 PDF](https://cdn.openai.com/pdf/ten-proofs-oai.pdf) ｜ [Lean 证明仓库 openai/ten-proofs](https://github.com/openai/ten-proofs)

  > 注：Astra 尚未发布，能力描述多来自 OpenAI 官方页面与 The Information 报道；是否命名为 GPT-6 或 GPT-5.7 未定。Anthropic 研究员 Levent Alpöge 随后用 Fable 在 24 小时内复现其中 5 项（观点/未同行评审）。

## 训练与数据层

- **Explorative Modeling（XM）：生成模型的端到端训练新范式（arXiv:2607.27372，7月29日提交）**
  - 简介：UIUC 与哈佛团队提出新范式 Explorative Modeling，把生成模型从"训练只学一小步、推理反复展开"的非端到端现状，改成可在训练时就做 best-of-K 探索、推理时一次前向生成，并验证了"探索"作为继参数、数据之后的第三根 scaling 轴。
  - 技术原理：根因诊断——主流生成模型用重构损失训练，多 mode 目标会被平均成"mode blurring"（最优解恰恰最不像真实数据），扩散/自回归靠把生成拆成小步绕过这个问题，却导致训练-推理不一致与 exposure bias。XM 的解法是一个 3-5 行 for 循环：每个训练步生成 K 个候选、只对离真实数据最近的那一个回传梯度，不同输入噪声各自"认领"不同 mode。把探索加到扩散/流/Jumpy/掩码扩散语言模型上，图像/视频/语言三模态性能单调提升，且随数据/模型/算力放大收益递增（数据放大增益 7%→36%，算力 3 倍时效率增益翻倍多；FLOP 效率 4.1×、样本效率 6.2×、参数效率 47%）。极限推到端到端：Explorative Policy 一次前向追平需 100 次前向的 Diffusion Policy，Explorative World Model 用 1/16~1/256 的推理算力做到更好平均表现。作者坦承纯 Forward XM 在极多 mode 分布上仍太贵，自回归 LM 是最难啃的骨头。
  - 链接：[论文 arXiv:2607.27372](https://arxiv.org/abs/2607.27372)

## 多模态 / 世界模型 / 生成

- **MiniMax H3：开源全模态生成模型（7月31日发布，8月3日开源权重）**
  - 简介：MiniMax（稀宇科技）通用全模态生成模型，统一理解文本/图像/视频/音频上下文，直出最高 2K 分辨率、15 秒、原生立体声音频的视频；在 Artificial Analysis 有声视频编辑榜以 1130 Elo 居首。基于 MiniMax H3 Community License 开源，首日 16 家芯片/平台完成适配。
  - 技术原理：核心设计是"任务泛化"——抛弃 Hailuo-02 架构，不再分 T2I/I2V/首尾帧/主体参考等独立专家，而在单一预训练框架里早融合所有模态与任务，用自然语言描述参考/编辑关系作为可泛化桥梁（Contextual Omni Representation，素材约 100K token 推理蒸馏到 4K）。关键技术：H3-VAE 重写 tokenizer 带来 4× 序列长度收益（高压缩率支撑原生 2K）；H3-Omni Transformer 按理解/生成异构 workload 分别调优硬件利用率 + 跨样本负载均衡，端到端训练吞吐近 +30%；In-context Regeneration 用基模对自己的低分辨率结果做上下文重生成（而非专用超分），复用原上下文恢复小文字等细节。2K 每秒价格不到主流模型 1/3。
  - 链接：[官方发布博客](https://www.minimax.io/blog/minimax-h3) ｜ [HuggingFace 权重 MiniMaxAI/MiniMax-H3](https://huggingface.co/MiniMaxAI/MiniMax-H3)

## 评估与基准

- **OSWorld 首破 90%：实在 Agent 90.2%（Agentic Framework 双榜第一）**
  - 简介：Computer-Use Agent 权威基准 OSWorld（NeurIPS 2024，港大/CMU/滑铁卢发起，361 个真实桌面任务、机器自动判定）首次有方案突破 90%——国内实在智能的"实在 Agent"以 90.2% 并列总榜与 Agentic Framework 分榜第一，2024 年顶级 AI 仅 12.2%、2025 年底 72.6%、2026 年 5 月 83.6%。
  - 技术原理：该方案走"通用模型 + 工程架构（Harness）"路线而非专用模型，印证 Agent = Model + Harness 的行业共识——同模型下仅改进 Harness 可在 OSWorld 拉开 6-17 个百分点。细分：跨应用协同 78.81/93（领先第二名近 10 分）、GIMP 图像处理 24/26、系统底层操作 24/24 满分。核心是"API 优先、GUI 兜底"的混合调度 + 长链路状态/记忆管理 + 全链路可审计日志 + 端侧轻量模型与云端 VLM 混合调度。信号：智能体竞争焦点正从"模型参数"转向"Harness 工程化 + 真实场景数据"；但 361 任务以短周期单应用为主，距工业级 99.99% 可靠性仍有差距。
  - 链接：[OSWorld 基准官网（含榜单）](https://os-world.github.io/) ｜ [NeurIPS 2024 论文 arXiv:2404.07972](https://arxiv.org/abs/2404.07972)

## 端侧 / 小模型

- **BarunLM-35M：单 H200 训出的"百 M 内最好小模型"（8月2日）**
  - 简介：独立开发者 Harshal Singh 用单张 H200 训出 35M 参数基础语言模型，自称"参数量 <100M 中最好"，在九项零样本基准平均 41.01%，超约 6.55 倍体量的 Liquid AI LFM2.5-230M-Base 及 GPT-2/Pythia-160M。Apache 2.0。
  - 技术原理：12 层、隐藏 448、7 查询头 + 1 共享 KV（GQA）。两个关键设计：(1) 3:1 交替局部/全局注意力——连续三层只看前后 256 token、第四层全局交换一次，降低计算又不切断长距离；(2) 可学习残差选择器，每四层在多个中间表示间决定保留哪些，缓解小模型容量有限下早期有效特征被覆盖。另组合 50% Partial RoPE、QK-Norm、门控注意力输出、bounded SwiGLU、嵌入权重 tying，词表压到 16384。约 57 亿 token 预训练（FineWeb-Edu/Cosmopedia v2/FineMath-4+/DCLM/代码），Muon 优化器，单 H200 训 40690 步。定位为紧凑 LM 研究/教学，非生产用。
  - 链接：[GitHub harrrshall/barunlm-35m](https://github.com/harrrshall/barunlm-35m) ｜ [HuggingFace harrrshall/BarunLM-35M](https://huggingface.co/harrrshall/BarunLM-35M)
