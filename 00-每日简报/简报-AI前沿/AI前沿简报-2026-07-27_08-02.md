## 基座模型与开源大模型

- **Kimi K3（Moonshot AI，2.8T MoE 开放权重）**
  - 简介：月之暗面 7/27 开源旗舰模型，总参数 2.8T、每 token 激活约 104B，原生视觉理解（MoonViT-V2），100 万 token 上下文，定位长程编程、知识工作与复杂推理。同步开放三项训练基础设施（MoonEP、FlashKDA、AgentEnv）。
  - 技术原理：93 层网络中 69 层用自研线性注意力 KDA（Kimi Delta Attention，带通道遗忘门的循环注意力，把长上下文计算量压到近线性）、24 层 Gated MLA；引入 Attention Residuals（每层读取全部前置层特征）缓解超深网络信号衰减；MoE 为 Stable LatentMoE，896 个路由专家中每 token 选 16 个+2 个共享专家，用 Quantile Balancing 替代传统负载均衡超参，激活函数 SiTU-GLU；从 SFT 阶段即做量化感知训练，发布权重为原生 MXFP4（约 1.56 TB，96 个 safetensors 分片）。官方称相对 K2 缩放效率提升约 2.5 倍。
  - 链接：[技术报告 PDF（GitHub）](https://github.com/MoonshotAI/Kimi-K3/blob/main/k3_tech_report.pdf) ｜ [模型权重（HuggingFace）](https://huggingface.co/moonshotai/Kimi-K3) ｜ [官方技术博客](https://kimi.com/blog/kimi-k3)

- **DeepSeek-V4-Flash 正式版（V4-Flash-0731，7/31 公测）**
  - 简介：DeepSeek 7/31 上线 V4-Flash 正式版 API 公测。架构与预览版一致（总参 284B、激活 13B 的 MoE，100 万 token 上下文，最大输出 384K），本轮提升全部来自重新后训练，Agent/编码能力大幅跃升，并新增原生 Responses API 与 Codex 适配。
  - 技术原理：沿用 V4 的混合注意力（SWA/CSA/HCA 按层混合）+ Hyper-Connection 残差结构；1M 上下文下 KV Cache 与 Attention 计算经滑窗+压缩算法压到约 10%/7%；后训练针对工具调用与多步任务强化，Terminal-Bench 2.1 报 82.7、Toolathlon Verified 70.3、DeepSWE 从预览版 7.3 跃升至 54.4（厂商自测数据，待独立验证）。
  - 链接：[模型卡（HuggingFace）](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash) ｜ [DeepSeek-V4 论文 arXiv:2606.19348](https://arxiv.org/abs/2606.19348) ｜ [API 文档（官方）](https://api-docs.deepseek.com)

- **MiniMax H3（全模态生成模型，7/31 发布并开源权重）**
  - 简介：MiniMax 7/31 发布并开源新一代通用视频/音视频生成模型 H3，统一理解文本/图像/视频/音频，生成最高 2K、最长 15 秒、带原生立体声的视频，面向广告/电商/UI/游戏等。
  - 技术原理：核心是联合音视频扩散 Transformer（DiT，hidden 5376、50 层+2 层 token refiner），把视频 latent（24 通道）与音频 latent（32 通道）拉平为一条长序列联合去噪，跨模态注意力保证声画对齐；采样为 flow matching（默认 50 步，视频/音频各自 flow-shift）；H3-VAE 重构 tokenizer，高压缩比带来 4 倍有效序列长度，是原生 2K 的基础；2K 通过 In-Context Regeneration（让基础模型在上下文里再生低分辨率输出）而非独立超分模块实现。权重以 MiniMax H3 Community License 发布。
  - 链接：[官方技术博客](https://www.minimax.io/blog/minimax-h3) ｜ [模型权重（HuggingFace）](https://huggingface.co/MiniMaxAI/MiniMax-H3)

## 推理模型与 AI for Science

- **OpenAI Astra · Ten Proofs（8/1）**
  - 简介：OpenAI 披露下一代模型 Astra 的内部版本，公开其在十个长期未解数学/理论计算机问题上的新结果（高维球堆积、非 sofic 群、Connes 刚性猜想、多色拉姆齐数等），并以 249 页主论文+62 页解题思路+GitHub Lean 证书形式发布。按 Sol API 折算总推理成本约 2000 美元。
  - 技术原理：Astra 自主生成数学论证，人类研究员协助整理手稿，再由模型将每个论证转化为 Lean 形式化证明证书供内核核验；这是继 5 月 AI 发现 Erdős 单位距离猜想反例后的延续，方向是 test-time compute 驱动的科研协作。注意：成果署名问题（AI 生成证明如何归属）被 OpenAI 单独讨论，数学界对其"理解"仍有争议。
  - 链接：[主论文 PDF（cdn.openai.com）](https://cdn.openai.com/pdf/ten-proofs-oai.pdf) ｜ [Lean 证书仓库（GitHub）](https://github.com/openai/ten-proofs) ｜ [解题思路 walkthrough PDF](https://cdn.openai.com/pdf/reasoning-walkthroughs.pdf)

## Agent / 记忆系统 / RAG（arXiv 7/29 批次）

- **InferScale：面向个性化大模型服务的 GPU 原生 KV 注入系统（arXiv:2607.27090）**
  - 简介：解决 Mem0/MemGPT/Zep 等记忆系统把检索到的记忆拼回 prompt 导致 vLLM 反复预填充、首字延迟（TTFT）随检索量增长的问题。
  - 技术原理：预先把每条记忆事实算成 KV 状态存到 GPU，服务时按语义检索后直接注入 vLLM 的 paged cache，跳过预填充；针对 RoPE 位置编码下动态拼接记忆的难题，提出 Chunked RoPE（存旋转前的 key、注入时再按服务时位置旋转）；用 Context-Window Encoding 缓解独立编码丢失跨事实上下文的问题。k=50 时 TTFT 降 72-79%，吞吐 3.7-4.5 倍，且无需改引擎或微调。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.27090)

- **BM25 Wins at Scale：四种 RAG 范式的规模化研究（arXiv:2607.26497）**
  - 简介：中科大/ Metastone 等团队在 28 级嵌套语料（约 1k→512k 文档）上严格对比词项/稠密/图/智能体四种 RAG 范式的准确率-成本 scaling，结论是"规模依赖的交叉"而非无条件赢家。
  - 技术原理：在固定问题、固定相关/对抗文档的受控梯子上，File-System Agent 在小规模领先但每答案消耗 39 倍查询 token、全规模落后近 20 分；约 1000 万语料 token 处 BM25 反超并在此后所有更大规模领先，且无需 LLM 构建即占据帕累托前沿低成本端；图 RAG 在规模化前撞构建墙。机制：全局候选排序在大规模下更重要，智能体推理应排在 BM25 召回之后而非取代它（Agent+BM25 全规模 69.4 vs 原始 agent 36.9）。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.26497)

- **图原生双时态记忆存储（A Graph-Native Bitemporal Memory Store，arXiv:2607.26520）**
  - 简介：为对话式 AI 智能体设计持久化、隐私保护、时间感知的长期记忆检索，不耗尽上下文窗口。
  - 技术原理：采用双时态属性图架构（记录事件发生时间与系统记录时间两条时间轴），支持"时间点语义"检索（回溯某历史时刻的记忆状态），把记忆持久化与上下文解耦。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.26520)

- **VITAL-RAG：编码智能体上下文分配的不变性竞争（arXiv:2607.26937）**
  - 简介：针对编码智能体 RAG 中"去冗余"与"保语义"相互冲突的问题，提出上下文分配策略。
  - 技术原理：识别出编码 RAG 的"不变性竞争"问题，提出基于规范代码对象的证据组织方法，在多个编码基准上领先同时显著降 token。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.26937)

- **KAMR：知识对齐的多跳检索（arXiv:2607.27136）**
  - 简介：面向知识图谱的多跳检索框架，区分锚点三元组与连接三元组以提升 RAG 接地性。
  - 技术原理：两阶段检索（全局锚点检索+局部扩展），用查询-三元组对齐与对比学习目标区分两类三元组，改善查询与三元组对齐效果。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.27136)

- **RAG 系统的蜕变测试（When Knowledge Changes，arXiv:2607.26843）**
  - 简介：评估 RAG 在文档语料库动态变化下的鲁棒性与一致性。
  - 技术原理：形式化 RAG 故障分类法，开发 11 种蜕变测试变异算子（模拟知识变更），故障检测优于 RAGAS 等静态指标。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.26843)

- **基于文件系统的 LLM 智能体记忆（Filesystem-Based Memory for LLM Agents，arXiv:2607.26637）**
  - 简介：研究智能体如何用文件系统组织、演化与维护长期记忆（59 页，含组织/演化/可持续性分析）。
  - 技术原理：把记忆以文件/目录结构管理而非塞进 prompt，研究其组织模式、随时间演化与可持续维护机制。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.26637)

## 评估与基准

- **Setoka：个性化智能体分层用户理解基准（arXiv:2607.27056）**
  - 简介：评估个性化智能体在异构数据上的分层用户理解能力，揭示当前记忆系统在"抽象用户特质推理"上的差距。
  - 技术原理：合成四个认知层级的异构数据，基于心理测量学的合成数据生成流水线构造基准。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.27056)

  - 技术原理：基于真实已公开 CVE 构建复现任务集，强调可复现与不依赖顶级闭源模型。
  - 链接：[arXiv 论文](https://arxiv.org/abs/2607.27030)

## 安全 / 红队

- **MemSecBench：智能体记忆投毒追踪（arXiv:2607.27080）**
  - 简介：系统性追踪 Agent 记忆系统从持久化被投毒到后果与修复的全链路安全问题。
