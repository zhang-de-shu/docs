# 重设计技能

## 工作方式

应用于现有项目时，遵循以下顺序：

1. **扫描** — 通读代码库。识别框架、样式方法（Tailwind、原生 CSS、styled-components 等）以及当前的设计模式。
2. **诊断** — 逐项执行下方审计。列出你发现的每一个通用模式、弱点和缺失状态。
3. **修复** — 在现有技术栈基础上应用针对性的升级。不要从头重写。改进已有的部分。

## 设计审计

### 字体排印

检查以下问题并修复：

- **浏览器默认字体或到处使用 Inter。** 换成有性格的字体。好的选择：`Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`。编辑风/创意类项目可以用衬线标题搭配无衬线正文。
- **标题缺乏存在感。** 增大展示文字的字号、收紧字距、减小行高。标题应当感觉厚重且有意图。
- **正文太宽。** 将段落宽度限制在约 65 个字符。增大行高提升可读性。
- **只使用 Regular (400) 和 Bold (700) 字重。** 引入 Medium (500) 和 SemiBold (600) 以获得更细腻的层级。
- **比例字体中的数字。** 数据密集型界面使用等宽字体或启用表格数字（`font-variant-numeric: tabular-nums`）。
- **缺少字距调整。** 大标题使用负字距，小型大写或标签使用正字距。
- **到处都是全大写的副标题。** 尝试小写斜体、句首大写或小型大写。
- **孤行词。** 单独落在最后一行的单个词。用 `text-wrap: balance` 或 `text-wrap: pretty` 修复。

### 色彩与表面

- **纯 `#000000` 背景。** 换成近黑、深炭色或带色调的深色（`#0a0a0a`、`#121212` 或深藏青）。
- **过度饱和的强调色。** 饱和度保持在 80% 以下。降低强调色的饱和度，使其与中性色融合而不是刺眼。
- **超过一个强调色。** 选一个。去掉其余的。一致性胜过多样性。
- **混用暖灰和冷灰。** 坚持一个灰色系。为所有灰色染上统一的色调（暖色或冷色，二者不可兼得）。
- **紫/蓝 "AI 渐变" 美学。** 这是最常见的 AI 设计指纹。换成中性底色加一个经过深思的强调色。
- **通用的 `box-shadow`。** 将阴影染色以匹配背景色调。使用彩色阴影（例如蓝色背景上的深蓝阴影），而不是低不透明度的纯黑。
- **零纹理的扁平设计。** 为背景添加细腻的噪点、颗粒或微型图案。纯扁平矢量感觉毫无生气。
- **完全均匀的渐变。** 用径向渐变、噪点叠加或网格渐变打破均匀感，而不是标准的 45 度线性渐变。
- **光照方向不一致。** 审计所有阴影，确保它们暗示单一、一致的光源。
- **亮色模式页面中随机的暗色区块（或反之）。** 单个深色背景区块打破原本明亮的页面，看起来像复制粘贴事故。要么全面采用暗色模式，要么全程保持一致的背景色调。如果需要对比，使用同一调色板中略深的色调——而不是在奶油色页面中间突然跳到 `#111`。
- **空洞、扁平、无视觉层次的区块。** 只有文字加素色背景的区块感觉未完成。添加高质量的背景图（模糊、叠加或蒙版）、细腻的图案或氛围渐变。无真实素材时使用可靠的占位图源，如 `https://picsum.photos/seed/{name}/1920/1080`。尝试在 hero 区块、功能区块或 CTA 后面使用背景图——即使是低不透明度的细腻全宽照片也能增加存在感。

### 布局

- **一切居中且对称。** 用偏置边距、混合宽高比，或在居中内容上使用左对齐标题来打破对称。
- **三列等宽卡片作为功能行。** 这是最通用的 AI 布局。换成双列之字形、不对称网格、横向滚动或瀑布流布局。
- **全屏区块使用 `height: 100vh`。** 换成 `min-height: 100dvh`，防止移动浏览器上的布局跳动（iOS Safari 视口 bug）。
- **复杂的 flexbox 百分比计算。** 换成 CSS Grid，获得可靠的多列结构。
- **没有 max-width 容器。** 添加容器约束（约 1200-1440px）配合自动边距，避免内容在宽屏上撑满边缘。
- **flexbox 强制卡片等高。** 内容长短不一时允许可变高度或使用瀑布流。
- **所有元素统一的圆角半径。** 变化半径：内部元素更紧凑，容器更柔和。
- **没有重叠或层次。** 元素平平地并排摆放。使用负边距创造层叠与视觉深度。
- **对称的垂直内边距。** 上下内边距总是相同。按视觉感受调整——底部内边距通常需要略大一些。
- **仪表盘总是左侧边栏。** 尝试顶部导航、悬浮命令菜单或可折叠面板。
- **缺少留白。** 把间距翻倍。让设计呼吸。密集布局适合数据仪表盘，不适合营销页面。
- **卡片组中的按钮没有底部对齐。** 当卡片内容长短不一时，CTA 会停在随机高度。将按钮固定在每张卡片底部，无论上方内容如何都形成一条干净的水平线。
- **功能列表的起始垂直位置不同。** 在定价表或对比卡片中，功能列表应在所有列中从相同的 Y 位置开始。在列表上方使用一致的间距，或使用固定高度的标题/价格区块。
- **并排元素的垂直节奏不一致。** 并排放置卡片、列或面板时，在所有项目间对齐共享元素（标题、描述、价格、按钮）。基线错位会让布局看起来像坏掉了。
- **数学对齐但视觉上看起来不对。** 数学上的居中未必让眼睛觉得居中。文字旁的图标、圆形中的播放按钮、按钮中的文字，通常需要 1-2px 的视觉微调才感觉正确。

### 交互与状态

- **按钮没有悬停状态。** 添加悬停时的背景变化、轻微缩放或位移。
- **没有按下/激活反馈。** 添加细腻的 `scale(0.98)` 或 `translateY(1px)` 按下效果，模拟物理点击。
- **零时长的瞬间过渡。** 为所有交互元素添加平滑的过渡（200-300ms）。
- **缺少焦点环。** 确保键盘导航有可见的焦点指示。这是无障碍要求，不是可选项。
- **没有加载状态。** 用与布局形状匹配的骨架屏替代通用的圆形加载器。
- **没有空状态。** 什么都不显示的空仪表盘是错失的机会。设计一个完整的"开始使用"视图。
- **没有错误状态。** 为表单添加清晰的行内错误信息。不要使用 `window.alert()`。
- **死链接。** 链接到 `#` 的按钮。要么链接到真实目标，要么在视觉上禁用它们。
- **导航中没有当前页面指示。** 为激活的导航链接设置不同样式，让用户知道自己在哪里。
- **滚动跳动。** 锚点点击瞬间跳转。添加 `scroll-behavior: smooth`。
- **动画使用 `top`、`left`、`width`、`height`。** 切换到 `transform` 和 `opacity`，获得 GPU 加速的平滑动画。

### 内容

- **"John Doe"、"Jane Smith" 之类的通用名字。** 使用多样、听起来真实的名字。
- **`99.99%`、`50%`、`$100.00` 之类的假整数。** 使用有机、凌乱的数据：`47.2%`、`$99.00`、`+1 (312) 847-1928`。
- **"Acme Corp"、"Nexus"、"SmartFlow" 之类的占位公司名。** 虚构贴合语境、可信的品牌名。
- **AI 文案陈词滥调。** 绝不使用 "Elevate"、"Seamless"、"Unleash"、"Next-Gen"、"Game-changer"、"Delve"、"Tapestry" 或 "In the world of..."。写平实、具体的语言。
- **成功消息中的感叹号。** 删掉它们。要自信，不要喧哗。
- **"Oops!" 式错误消息。** 直接表达："Connection failed. Please try again."
- **被动语态。** 使用主动语态：用 "We couldn't save your changes" 而不是 "Mistakes were made."
- **所有博客文章日期相同。** 随机化日期使其看起来真实。
- **多个用户使用同一张头像图片。** 为每个不同的人使用唯一的素材。
- **Lorem Ipsum。** 绝不使用占位拉丁文。写真实的草稿文案。
- **每个标题都用标题大写（Title Case）。** 改用句首大写（sentence case）。

### 组件模式

- **通用的卡片外观（边框 + 阴影 + 白色背景）。** 去掉边框，或只用背景色，或只用间距。卡片只有在抬升能传达层级时才应该存在。
- **总是一个实心按钮 + 一个幽灵按钮。** 添加文字链接或三级样式以减少视觉噪音。
- **胶囊形的 "New" 和 "Beta" 徽章。** 尝试方形徽章、旗标或纯文本标签。
- **手风琴 FAQ 区块。** 使用并排列表、可搜索的帮助或行内渐进式披露。
- **带圆点的三卡轮播见证。** 换成瀑布流墙、嵌入的社交帖子，或单条轮换的引言。
- **三塔式定价表。** 用颜色和强调突出推荐档位，而不只是额外的高度。
- **什么都用模态框。** 简单操作用行内编辑、滑出面板或可展开区块，而不是弹窗。
- **只用圆形头像。** 尝试方圆形（squircle）或圆角方形，减少通用感。
- **亮/暗切换总是太阳/月亮开关。** 使用下拉菜单、系统偏好检测，或将其整合进设置。
- **4 列的页脚链接农场。** 简化。聚焦主要导航路径和法定必需链接。

### 图标

- **只用 Lucide 或 Feather 图标。** 这些是"默认"的 AI 图标选择。使用 Phosphor、Heroicons 或定制图标集来体现差异化。
- **"Launch" 用火箭，"Security" 用盾牌。** 用不那么直白的图标替换陈词滥调的隐喻（闪电、指纹、火花、保险库）。
- **图标间描边宽度不一致。** 审计所有图标并统一为一种描边粗细。
- **缺少 favicon。** 始终包含品牌化的 favicon。
- **图库的"多元化团队"照片。** 使用真实的团队照片、抓拍，或统一的插画风格，而不是诡异的图库图像。

### 代码质量

- **Div 汤。** 使用语义化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- **内联样式与 CSS 类混用。** 将所有样式移入项目的样式系统。
- **硬编码的像素宽度。** 使用相对单位（`%`、`rem`、`em`、`max-width`）实现弹性布局。
- **图片缺少 alt 文本。** 为屏幕阅读器描述图片内容。有意义的图片绝不留下 `alt=""` 或 `alt="image"`。
- **`9999` 之类的随意 z-index 值。** 在主题/变量中建立干净的 z-index 阶梯。
- **被注释掉的死代码。** 交付前移除所有调试残留。
- **导入幻觉。** 检查每个导入是否真实存在于 `package.json` 或项目依赖中。
- **缺少 meta 标签。** 添加合适的 `<title>`、`description`、`og:image` 和社交分享 meta 标签。

### 战略性遗漏（AI 通常会忘记的东西）

- **没有法律链接。** 在页脚添加隐私政策和服务条款链接。
- **没有"返回"导航。** 用户流程中的死胡同。每个页面都需要返回的路径。
- **没有自定义 404 页面。** 设计一个有帮助、品牌化的"页面未找到"体验。
- **没有表单验证。** 为邮箱、必填字段和格式检查添加客户端验证。
- **没有"跳到内容"链接。** 对键盘用户必不可少。添加一个隐藏的跳转链接。
- **没有 Cookie 同意。** 如果所在司法辖区有要求，添加合规的同意横幅。

## 升级技巧

升级项目时，从以下高影响力技巧中提取，替换通用模式：

### 字体排印升级
- **可变字体动画。** 在滚动或悬停时插值字重或字宽，让文字感觉有生命。
- **描边到填充过渡。** 文字从描边轮廓开始，在滚动入场或交互时填充颜色。
- **文字蒙版揭示。** 大型字体排印作为窗口，展示其后的视频或动态图像。

### 布局升级
- **破碎网格 / 不对称。** 刻意无视列结构的元素——重叠、溢出屏幕，或以有计算的随机性偏置。
- **留白最大化。** 激进地使用负空间，迫使焦点集中在单一元素上。
- **视差卡片堆叠。** 在滚动期间固定并物理地相互堆叠的区块。
- **分屏滚动。** 屏幕两半向相反方向滑动。

### 动效升级
- **带惯性的平滑滚动。** 将滚动从浏览器默认中解耦，获得更厚重、电影感的体验。
- **错落入场。** 元素以轻微延迟级联入场，结合 Y 轴位移与透明度淡入。绝不一次性挂载所有元素。
- **弹簧物理。** 用基于弹簧的运动替代线性缓动，为所有交互元素带来自然、有重量感的体验。
- **滚动驱动揭示。** 内容通过扩张的蒙版、擦除或与滚动进度绑定的 SVG 路径描画进入。

### 表面升级
- **真正的玻璃拟态。** 超越 `backdrop-filter: blur`。添加 1px 内边框和细腻的内阴影以模拟边缘折射。
- **聚光灯边框。** 在光标下动态点亮的卡片边框。
- **颗粒与噪点叠加。** 一个固定的、pointer-events-none 的叠加层，带细腻噪点，打破数字的扁平感。
- **彩色染色阴影。** 带有背景色调的阴影，而不是通用的黑色。

## 修复优先级

按以下顺序应用改动，以最小风险获得最大视觉影响：

1. **更换字体** — 最立竿见影的提升，风险最低
2. **清理色彩调色板** — 移除冲突或过度饱和的颜色
3. **悬停与激活状态** — 让界面感觉有生命
4. **布局与间距** — 合适的网格、max-width、一致的内边距
5. **替换通用组件** — 用现代方案替换陈词滥调的模式
6. **添加加载、空和错误状态** — 让它感觉完整
7. **打磨字体比例与间距** — 高端的最后点睛

## 规则

- 与现有技术栈协同工作。不迁移框架或样式库。
- 不破坏现有功能。每次改动后都测试。
- 导入任何新库之前，先检查项目的依赖文件。
- 如果项目使用 Tailwind，修改配置前先检查版本（v3 还是 v4）。
- 如果项目没有框架，使用原生 CSS。
- 保持改动可审查、聚焦。小而针对性的改进优于大重写。
