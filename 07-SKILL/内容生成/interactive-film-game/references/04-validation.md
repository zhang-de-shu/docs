# 阶段四：全局校验（validate）

打通「生成 → 诊断 → 修复 → 交付」回路的最后一环。

## 完成标准

- 本地校验脚本通过率达标（error 清零；warning 尽量清零），向用户展示通过率前后对比。
- 导演终审（如触发）已出报告；mustFix 项已修复或有用户明确豁免。
- 交付物已导出。

## 工作步骤

1. **本地校验（执行代码）**：本地校验是确定性规则检测，不逐项人工/AI 自查，直接运行脚本：
    ```bash
    alink scripts/validate.js <项目JSON路径> --write
    ```
    脚本执行 26 项检测（结构完整性 16 项 + 叙事质量 10 项），自动遍历节点图与条件表达式，输出 ValidationReport（issues 含 level/code/message/relatedIds）并通过率 = 100 − error×20 − warning×8 − info×2（下限 0）；加 `--write` 时报告直接写入 project.json 的 `lastValidation`（校验不通过也会写入，便于修复后对比）。error > 0 时进程以非零码退出。
    - 脚本内置：可达性 BFS 承认 explore 返回边；条件表达式 lint（括号匹配、`varName op value` 子式校验）；软锁检测（变量阈值 > 全图 variableEffects 理论上界 → UNSATISFIABLE_CONDITION）。
    - 脚本失败或 JSON 不符合 `../../references/data-model.md` 结构时报错退出——先修数据，不要跳过校验。
    - 校验结果由脚本 `--write` 写入 Project 的 `lastValidation`，不由 AI 手工转录。

2. **自我检查**：校验后用一句话自检——结构问题（死路/断链/不可达）、互动密度（即死 BE 每章 4-8 个、normal 推进节点是否有 2-3 个真选择、变量写入后是否被读取回响）、结局分布（是否有终章单点扇出：多个结局共享同一前置选择节点）、叙事问题（情感节奏单调/选项重复/结局单一）、角色一致性（主要角色是否在主路径都有出场）是否还有遗漏，发现问题直接修正后重跑脚本，无需输出独立的 AI 分析报告。

3. **五位专家导演终审（validate:director_review，可选）**：用户需要更严格创作评审时触发。五位评委各打 0-10 分，observation 必须引用具体节点标题，产出总分、greenlit 判定、mustFix 清单、standout_moment 高光点评。verdicts 数组必须恰好 5 项：
    - 斯皮尔伯格（情感冲击力）：观众会哭吗？主角旅程是否有内在弧度？最关键情感时刻是否成立？依据：情感真实性、可共情度、结局情感落点。
    - 麦基（结构完整性）：故事脊柱是否成立？中点大反转是否存在？最终选择是否是全片最难的道德抉择？依据：故事脊柱强度、张力节奏、选择的戏剧代价。
    - 乔布斯（产品体验）：玩家是否感到自己在做真实有意义的选择？有没有"one more thing"时刻——让一切重新被理解的反转？依据：选择的感知权重、体验流畅性、惊喜感。必须考察：即死 BE 密度是否达到每章 4-8 个、BE 恶果是否为性格测验而非随机惩罚（即死不等于真死——暴露/失败/崩塌/被逐皆可）、状态记忆是否有跨章回响兑现。
    - 角色心理学家（角色深度）：每个角色行为是否与伤痛/谎言/需要一致？关系张力是否来自真实心理冲突？依据：角色弧度一致性、心理真实性、关系动态。
    - 首席观众（可重玩性与传播）：看完第一遍想立刻重玩吗？不同结局是否真的展现不同人生观？必须考察：选择路径是否导致实质不同的剧情体验（还是只有对白微调）；首通与二周目体验落差是否足以形成口碑传播；是否存在"隐藏内容"驱动探索欲。
    - 输入需包含项目统计（总节点/分支节点/假分支——所有选项指向同一节点/平均对白行数/内容稀薄节点/平均紧张度）与假分支警告列表。
    - 输出模版：{"verdicts":[{"lens":"斯皮尔伯格·情感冲击力","score":7,"observation":"必须引用具体节点标题，指出哪里扎实、哪里不足","note":"一条可执行的改进建议"}，…共5项],"overallScore":7,"greenlit":false,"executiveSummary":"项目…核心问题是…修复后建议绿灯。","mustFix":["逐条列出必须修改项，引用具体章/节点"],"standout_moment":"全剧目前最精彩的单一时刻——引用具体台词，说明它完成了什么"}

4. **定向修复**：按阶段二第 4 步（structure:targeted_fix）生成节点级补丁——只补不改写，已填对白不得清空；逐项采纳后**重跑校验脚本**，展示通过率前后对比。

5. **导出交付**：导出由脚本完成，**必须加 `--ink`**（三件交付物缺一不可）：
    ```bash
    alink scripts/export.js <项目JSON路径> <输出目录> --ink
    ```
    - **Markdown 剧本**（`剧本.md`）：按 章 → 节点 两级组织，每节点含场景头、场景描述、对白（说话人：台词）、玩家选项（含条件与变量效果标注）；BE 节点单独标注。
    - **JSON**（`project.json`）：完整 Project 数据（`../../references/data-model.md` 结构，事实来源）。
    - **ink**（`story.ink`，**必须生成**）：按 `../../references/ink-export.md` 规范产出（VAR 声明自洽、条件结构保留、变量名净化）。
    - 导出完成后核对输出目录中三个文件（剧本.md / project.json / story.ink）均存在且非空；缺任何一件视为未完成，补齐后再向用户交付。

## 产物

`lastValidation` / `directorReview` 写入 project.json；输出目录中的 `剧本.md`、`project.json`、`story.ink` 三件交付用户，报告剩余未修复项（如有）。
