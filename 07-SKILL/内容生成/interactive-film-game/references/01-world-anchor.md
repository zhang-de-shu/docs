
# 阶段一：世界锚点与规模规划（world / scale）

基于主 skill 已收集的设定（故事核心、核心主题、类型/风格、世界规则、目标时长单路径口径、结局数量、题材机制、多周目预期），产出世界锚点、角色、状态表、结局设计、回响映射表与体量方案。结构分层为 **章 → 小节（节点）两级**，没有幕这一层。

## 完成标准

以下字段全部填写并通过自我检查：
- `storyCore`（含"主角想要什么 + 什么在阻碍"的张力）、`theme`、`genre`、`worldRules`、`durationMinutes`（单路径口径）、`endingCount`
- 角色表（含四维心理字段，主角含 fatalFlaw 致命弱点；启用好感系统时标注好感对象）、状态表（必选层 + 题材层，核心变量合计 3-6 个）、结局设计（数量 = endingCount，含 BE/NE/HE/TE 阶层）、回响映射表（每个 Flag 一行：写入章 → 读取章/节点）
- 体量方案 `scalePlan`（仅此一套即选定方案）：每章 20-30 小节、每章 4-8 个即死 BE 岔口，章节大纲与故事设定贴合

## 工作步骤

1. **角色设计**：
    - 参考当前世界设定生成 **5-10 个**主要角色供用户采纳/修改/否决（业界参照：完蛋 6 位主要角色，隐形守护者 10 位以上；恋爱/群像题材偏多、悬疑独狼题材可偏少）。
    - 必须有1个主角(protagonist)，其余为对立角色(antagonist)/支线角色(support)
    - 每个角色的wound/lie/want/need要与故事核产生张力
    - **主角必须产出 `fatalFlaw`（致命弱点）**：一条"性格缺陷 → 恶果形式"映射（如"自负于推理→败于一步推理失误""重诺→为承诺涉险而全盘皆输"）——即死 BE 的本质是**这条路线的故事到此为止**（真死只是形式之一，暴露/任务失败/关系崩塌/被驱逐等命运性恶果同样成立），此映射是阶段二即死 BE 岔口的恶果库，BE 恶果必须从这里引用或呼应，不得随机编造。配角不填此项（配角的结局属于剧情编排，不是玩家选择导致的 BE）
    - 角色之间的关系要能自然制造冲突
    - 启用好感系统时：标注哪些角色是**好感对象**（好感线载体，其 relationship 变量进入状态表）
    - 如已有结局线，角色设计要能支撑结局路线的差异
    - 输出样例：{"characters":[{"name":"角色名","role":"protagonist","motivation":"核心动机","relationship":"与主线的关系","wound":"心理伤痛（过去的创伤）","lie":"内心谎言（用来保护自己的错误信念）","want":"外部欲望（想得到什么）","need":"内在需求（真正需要什么）","fatalFlaw":"致命弱点→恶果形式映射（仅主角，即死BE恶果库）"}]}

2. **状态表设计（先于结局设计——变量是选择的货币，结局是变量的读数）**：
    - **必选层（任何题材都要）**：
        - 剧情Flag **全剧 1-3 个**（布尔：看过某事件/拿到某证物/说过某话）——只记真正要跨章兑现的关键事件，宁少勿滥；每个 Flag 都必须有明确的回响计划（见回响映射表）
        - 路线/立场变量 **1-2 个**（整数累加，终章裁决用）
    - **题材层（按主 skill 收集的题材机制选配，0-2 个）**：
        - 好感度（情感线题材）：relationship 变量，量程约-5到+5；清零=心碎可触发角色中途 BE，拉满可直通专属篇
        - 存活状态（群像生存题材）：角色存活 Flag，死亡 = 后续章节内容裁剪（该角色内容缺席）
        - 怀疑度/信任度（阵营潜伏题材）：counter 变量，超阈值触发暴露 BE
    - 核心变量合计 **3-6 个**；全部变量共用同一套小整数量表，禁止百分比。玩家每做一次相关选择，变量以整数增量（通常+1，少数+2）累积，变量现实上限约为0-10。
    - 输出样例：{"variables":[{"name":"saw_letter","type":"flag","defaultValue":"0","description":"是否看过密信（第2章写入，第4章回响）"},{"name":"route_stance","type":"counter","defaultValue":"0","description":"路线立场累积，终章裁决用"}]}

3. **结局设计**：
    - 根据世界设定设计指定数量差异鲜明的结局供用户采纳/修改/否决，按 **BE/NE/HE/TE 阶层**组织：BE（中段即死，不占 endingCount 预算）+ NE 1-2 + HE 2-4 + TE 1（TE 是回收全部伏笔的真结局，读取 ≥3 个分散在全剧的 Flag/好感阈值；单周目高门槛或二周目目标按多周目预期定）。
    - 每个结局必须代表主题的不同维度（救赎/毁灭/妥协/真相…）
    - 结局之间的达成路径要互斥——选择不同的关键节点才能到达；每个主结局至少有 1 个专属前置小节
    - **结局条件只能引用状态表中已定义的变量**（变量先行、结局引用），不得为结局新造变量
    - 输出样例：{"endings":[{"id":"e1","title":"结局标题","type":"good","description":"此结局中玩家经历的最终命运，1-2句","triggerCondition":"达成此结局需要做的关键选择（具体）","avoidCondition":"哪些选择会让玩家偏离此结局","keyVariable":"courage>=4"}]}
        - triggerCondition：玩家需要做什么关键选择才能走向此结局（具体行为，非抽象描述）
        - avoidCondition：哪类选择会导致偏离此结局走向其他结局
        - keyVariable：引用状态表中的变量与阈值（0-10量表，阈值3-6），否则留空
        - type 只能是 good / bad / neutral / secret （secret 对应 TE 真结局，需要特别隐蔽的跨章条件组合）

4. **回响映射表**：
    - 为每个剧情 Flag 和每个核心变量规划"写入 → 读取"路径：**写入章（哪个选择写入）→ 读取章/节点（哪段对白/选项/门控兑现）**；关键 Flag 至少跨 1 章回响，全剧规划 1-2 处蝴蝶效应式回响（看似无关的小选择在终盘重构为陷阱）
    - 输出样例：{"echoPlan":[{"variable":"saw_letter","writeChapter":2,"readChapter":4,"echoDesc":"第4章角色引用密信内容，未看过则该段对白替换"},{"variable":"spare_beggar","writeChapter":3,"readChapter":5,"echoDesc":"蝴蝶效应：乞丐在终章回报/指认"}]}
    - 此表是阶段二生成"回响读取节点"的直接输入；没有回响计划的 Flag 不应进入状态表

5. **自我检查**：生成完成后用一句话快速自检——世界规则是否自洽、角色是否与故事核匹配、主角的 fatalFlaw 是否能支撑多种恶果形式、故事核是否包含"欲望+阻碍"的张力、规则是否是逼迫角色做艰难选择的引擎（而非设定装饰）、角色是否有内心撕裂、主题能否通过玩家选择体现、每个 Flag 是否都有回响计划。发现问题直接修正后再交付，无需输出独立审查报告。

6. **声纹卡（可选）**：为主要角色生成声音指纹（speaking_rhythm / vocabulary / defense_mechanism / lie_tells / sample_lines），供阶段三对白创作约束风格一致性。
    - 输出模版：{"speaking_rhythm":"说话节奏（快/慢，短句/长句，直接/迂回）","vocabulary":"常用词汇类型和禁用词","defense_mechanism":"压力下的语言防御机制（如转移话题、反问、沉默）","lie_tells":"说谎时的语言特征（如过度解释、突然变得礼貌）","sample_lines":["一句展示其声音特征的示例台词","另一句"]}

7. **规模规划（scale）**：按 `domain-baseline.md` §2.1 的量化基准，由目标时长（单路径）换算唯一体量方案 `scalePlan`（章数、每章小节数 20-30、节点数、分支数、预估工时、章节大纲）。互动密度不打折，只砍章数——体量小时减章数，禁止压低每章小节数来凑小体量（否则退化为单线短剧）。
    - 输出模版：{"label":"方案定位（如：小程序互动剧）","chapterCount":5,"nodesPerChapter":25,"totalNodes":125,"totalBranches":35,"branchCount":30,"estimatedHours":150,"aiRationale":"依据目标市场与时长的定档理由","chapters":[{"title":"第一章：开端","brief":"主角登场，核心矛盾浮现"}]}（chapters 数组长度必须等于 chapterCount，章节标题和 brief 贴合输入的故事设定；章名可随状态变化，brief 中可注明状态变体）


## 产物

`worldAnchor` / `characters` / `variables` / `endingsDesign` / `scalePlan` 字段——**确认后立即写入项目目录的 `project.json`**（已含其他阶段字段则合并写入）。向用户展示后确认，方可进入阶段二（结构与分支）。
