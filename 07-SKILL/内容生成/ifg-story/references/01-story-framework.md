# 阶段一：故事线框架（story framework）

用户的输入是种子——可能是一句话、一个场景、或一个开头。AI 从种子直接生成完整的故事线框架。规模遵守 `domain-baseline.md` §2.1 的基准。

## 完成标准

- `storyCore`：从种子提炼，含"主角想要什么 + 什么在阻碍"的张力
- `timeSpan`：全剧的整体时间跨度
- `scalePlan`：章数、每章小节数 20-40、节点/分支数、chapters[]（每章 brief + 该章所处的时间点）
- **每章的场结构**：`scalePlan.chapters[].scenes[]`——每章几场、每场一句话内容（title + brief）；章间的时间跳跃在章 brief 里点明（"三年后""当夜·同一时间"）；序章的 brief 里注明其教学目标（教什么：选择/变量/BE 回溯）
- **结局与章节映射**：`endingsDesign[]` 每个结局标注 `chapter`（在哪个章收束），按 BE/NE/HE/TE 阶层组织
- `variables`（3-6 个精简核心变量）、主角 `fatalFlaw`（一条"性格缺陷→恶果形式"映射）、`echoPlan`（每个 Flag 一行写入→读取）

## 工作步骤

1. **读懂种子**：从用户输入中提取可用的戏剧胚子——谁受苦、谁想要、什么在阻碍、什么最反常。
2. **先定时间跨度，再切时间点**：故事必须横跨一段较长的真实时间（数月乃至数年）——用户种子里的事件往往只是引爆点，前后各有酝酿、发酵、余波。在跨度上切出 5 章左右的时间点（每个时间点可含一段短时间内的连续事件），章与章之间以时间跳跃相连。
3. **序章（prologue）**：正文第一章之前必设序章，承担两件事——①**背景交代**：把时间跨度、世界面貌、人物处境用可玩的方式（而非说明书）建立起来，序章结束时玩家应明白"这是个什么世界、主角是谁、风暴为何将至"；②**教学**：玩家在序章完成第一次选择、第一次变量感知、第一次（低压力的）即死 BE 或抉择示范，进入第一章时已掌握基本玩法。序章规模为正章的一半左右（约 10-15 节点），不计入正文章数；序章末尾的钩子直接把玩家推进第一章的事件引爆点。
4. **生成故事线**：在每个时间点上展开一章剧情弧（该时间点的卷入 → 挣扎 → 反转 → 收束），每章一段 brief；跨度带来的后果必须累积——前一时间点的选择在后一时间点以人物成长、关系变迁、世界变化的形式显现。
5. **划场**：每章按时空切 4-8 场，每场一句话（title + brief）。场是阶段二拆节点的直接单位。
6. **设计结局**：按领域基线 §3 的阶层（BE 中段若干不占预算 + NE 1-2 + HE 2-4 + TE 1），每个结局标注收束章；TE 需 ≥3 个跨章 Flag/阈值条件。
7. **定变量与 fatalFlaw**：3-6 个核心变量（路线/立场 1-2 + Flag 1-3 + 题材层 0-2），每个 Flag 有回响计划；主角一条 fatalFlaw 作为阶段二即死 BE 的恶果库。
8. **种子不清时**：给用户 2-3 个方向选项（不同类型/基调/真相走向），让用户挑选后再细化。

## 产物

`storyFramework`（storyCore / theme / genre / worldRules 一句话 / durationMinutes / endingCount）+ `scalePlan`（含 chapters[].scenes[]）+ `endingsDesign` + `variables` + 主角 `fatalFlaw` + `echoPlan`——确认后写入 `project.json`，进入阶段二。
