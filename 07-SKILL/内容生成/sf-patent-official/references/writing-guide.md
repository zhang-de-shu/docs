# 技术交底书各章节写作指南

## 1. 提案名称

格式：「一种 + [核心技术描述] + 方法/系统/装置」

好的命名：
- 一种基于性能指标的大模型Endpoint智能路由系统
- 一种高性能内存缓存
- 一种高性能并行计算方法

## 2. 背景技术

**2.1 现有技术介绍**

要求：面向技术小白，描述当前最接近的技术方案。
- 介绍技术领域和背景
- 说明现有技术的主流做法
- 语言通俗，避免过于专业的术语（如有术语需解释）

**2.2 现有技术的缺点 / 本发明解决的技术问题**

要求：客观指出问题，**不要过分夸大现有技术的缺点**。
- 明确列出 2-5 个具体问题
- 问题要与后续方案形成对应关系
- 可以用列表形式清晰呈现

## 3. 详细方案（最核心章节）

**3.1 核心发明点**

列出 2-4 个最关键的技术创新要素，每个用一句话概括。

**3.2 完整技术方案描述**

这是交底书最重要的部分，需遵循以下原则：

- **面向技术小白**：通俗易懂地解释
- **总-分结构**：先总体概述，再分步/分模块详细阐述
- **结合附图**：在关键位置标注 `（附图N：XXX示意图）`，每份交底书至少2张图
- **步骤化描述**：方法类用 S1、S2、S3... 步骤描述
- **具体参数**：涉及算法的要写出计算公式、阈值设定

不同类型的侧重点和附图要求：

| 类型 | 3.2 重点内容 | 必选附图 |
|------|------------|---------|
| 算法模型 | 模型结构（总-分）→ 训练方法 → 使用场景 | 模型结构图 + 训练/推理流程图 |
| 应用软件 | 系统架构 → 各模块功能 → 数据流 → 步骤 | 系统架构图 + 核心流程图 |
| 机械结构 | 整体结构 → 各部件关系 → 工作原理 | 结构示意图 + 部件详图 |
| 外观设计 | 六面视图 → 设计要素 → 外观特征 | 六面视图 + 立体效果图 |
| 通用 | 按逻辑自由组织，保证完整性 | 核心流程图 + 方案示意图 |

**3.3 技术效果**

要求：效果要与前面提出的问题一一对应。
- 2-5 个效果点
- 每个效果用一个关键词概括（高效性/精确性/可靠性/安全性等）
- 能量化的一定要量化（如"速度提升10倍"、"延迟从5分钟降到30秒"）

## 4. 技术补充

**4.1 替代方案**

目的：防止他人通过改变技术方案来绕开本发明。
- 提供 2-3 个可能的替代实现方案
- 每个替代方案简要描述即可

**4.2 术语说明**

- 所有英文缩写给出全称和中文注释
- 所有专有术语给出定义
- 格式：`术语（English Full Name）：中文解释`

**4.3 参考文献**

列出相关的专利/论文/技术文档链接（如有）。

## 5. 技术声明

**5.1 实施情况**（四选一）：
- □ 属于技术研发成果，未应用到实际产品
- □ 该方案已应用到实际产品，产品在公司内部应用
- □ 该方案确定应用到实际产品，将要或已经对外公开应用
- □ 不属于技术研发成果，未应用到实际产品

如已实施，需补充：项目名称、产品名称、计划实施时间、产品介绍。

**5.2 公开情况**：说明是否有对外公开计划（展会/宣讲/供应商/论文等）。

## 6. 信息追问话术库（配合 SKILL.md Step 2）

先读用户资料、自行归纳，仅对缺口用下列话术定向追问。同一类问题一次问清，不重复问已从资料得到的信息。

### 6.1 问题（背景技术）
- 「现有做法是怎样的？最接近的方案是哪种？」
- 「它在什么场景下会出问题？具体表现是什么？」
- 「这个问题有多严重？能给个量化数据吗（耗时/错误率/成本）？」

### 6.2 核心方案
- 「你的方案关键步骤有哪些？能按先后顺序说一遍吗？」
- 「和现有做法**最小的区别**是哪一点？」（创造性关键，见 review-guide.md）
- 「这个区别，一个熟练工程师能否轻易想到？为什么之前没人这么做？」
- 「涉及算法的话，有没有具体公式、阈值、参数设定？」

### 6.3 技术效果
- 「相比现有技术，好在哪几个方面？」
- 「能不能给「现有 vs 本方案」的量化对比？（如延迟从 X 降到 Y）」

### 6.4 实施情况（必问，资料里通常没有）
- 「这个方案已经用在哪个项目/产品里了？还是仅研发阶段？」
- 「有没有对外公开计划（展会/论文/供应商）？」

### 6.5 核心发明点确认（Step 3.1 卡点必问）
- 「我提炼出这几个核心发明点：①…②…③…——是不是真正的创新？」
- 「有没有更核心的点被我漏了？有没有把常规工程实现误当成创新？」
- 「哪个是最主要的发明点？」
