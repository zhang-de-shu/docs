# GLM-5.1 技术原理详解

> 发布方：智谱 AI（Z.ai，原 Zhipu AI）。GLM-5.1 于 2026-04-08 发布、以 **MIT 许可证开源**（权重在 Hugging Face `zai-org/GLM-5.1` 公开），是 GLM-5 系列的迭代版本，定位"复杂工程环境中可自主探索、持续改进、稳定交付"的高价值 Agentic Coding 模型。
> 本文重点讲**技术原理（机制怎么做的）**，而非罗列特性。核心四块：**自回归填空预训练**、**DSA 稀疏注意力**、**MoE 架构**、**异步 Agent 强化学习（slime 框架）**。
>
> ⚠️ 核实说明：GLM-5.1 本身**未单独发布技术报告**，其架构机制（DSA、MoE、异步 RL）主要承袭 GLM-5。GLM-5 有公开技术报告（arXiv:2602.15763《GLM-5: from Vibe Coding to Agentic Engineering》）。因此本文的**机制细节多以 GLM-5 技术报告为准**，GLM-5.1 在其上做工程迭代与昇腾适配；凡 GLM-5.1 专属、无法在官方来源核实的具体数字，均以 `> ⚠️ 待核实` 标注。

## 0. 先看全景：GLM-5.1 用四套机制解决四个矛盾

GLM-5.1 的设计可以用"四个矛盾、四套解法"来概括，这是理解全篇的主线：

| 矛盾 | 解法 | 作用 |
|------|------|------|
| 理解与生成不可兼得 | **自回归填空（autoregressive blank infilling）** | 一套目标同时覆盖 NLU + 有条件/无条件生成 |
| 模型越大、推理越贵 | **MoE + DSA 稀疏注意力** | 砍长上下文算力，长上下文能力不掉 |
| 训练与实战脱节 | **异步 Agent RL（slime 框架）** | 让模型在真实多步任务里成长 |
| 算力受限于单一硬件 | **国产芯片全栈适配（训练+推理）** | 昇腾/摩尔线程/海光/寒武纪/昆仑芯/沐曦/燧原 |

**关键能力指标**：约 **754B（7540 亿）总参数、约 40B 激活参数**的 MoE 架构（总参/激活 ≈ 18:1，推理成本接近 40B 密集模型）；具备**长达 8 小时连续自主工作**能力（METR 同口径评估下唯一达到 8 小时级的开源模型）；核心工程能力对齐 Claude Opus 4.6（SWE-bench Pro 上以 58.4 分首次超越 Opus 4.6 与 GPT-5.4）；在昇腾上实现 **Layer 级 MoE 绝对均衡**，华为云系统级优化使整体推理吞吐提升约 **30%**。

> ⚠️ 待核实："开源模型中首次实现 **1700 步连续工具调用**"——该数字见于第三方评测（BuildFastWithAI），用以说明"4 个月内自主步数从 20 步跃升到 1700 步"的能力曲线；**智谱官方 Demo 强调的口径**是"655 轮自主迭代""6000+ 工具调用""千轮工具调用"（如向量数据库优化、KernelBench Level 3）。两者量级一致但具体"1700"未见官方原文，保留待核实。

> **为什么强调"总参/激活 ≈ 18:1"**：MoE 的价值不在总参数大，而在"用很大的容量、付很小的单 token 算力"。754B 总参让模型有足够知识与能力容量，40B 激活让单次推理成本可控，这是它能在国产卡上实际部署、又能跑长任务的前提。

## 1. 自回归填空预训练（GLM 的"地基"机制）

要理解 GLM 系列为什么和 GPT/BERT 都不一样，必须从它的预训练目标讲起——这是 GLM 从初代起就坚持的招牌，5.1 仍以此为底座。

### 1.1 问题：三类任务的目标互相打架

传统预训练有三条路线，各有短板：
- **自编码（BERT）**：双向看上下文，强在"理解（NLU）"，但不擅长"生成"；
- **自回归（GPT）**：从左到右逐词生成，强在"生成"，但只能单向看，理解类任务吃亏；
- **编码器-解码器（T5）**：能兼顾，但结构重、参数利用率低。

没有一个框架能用**同一套目标**把"理解 + 有条件生成 + 无条件生成"都做好。

### 1.2 机制：把"挖空 + 自回归补全"合二为一

GLM 的解法叫**自回归填空（autoregressive blank infilling）**，原理一句话：

> **在输入文本里随机挖掉若干连续片段（span），然后让模型用自回归的方式，把这些被挖掉的片段一个一个"续写"回来。**

具体怎么做：
1. 给定输入 `x = [x1, ..., xn]`，**采样多个连续片段** `{s1, ..., sm}`（每个片段是一串连续 token）；
2. 把这些片段从原文挖走，留下带"空位"的文本（Part A）；被挖走的片段集中放到后面（Part B）；
3. 模型**双向地看 Part A**（保留了 BERT 式的理解能力），同时**自回归地生成 Part B 里每个空位的内容**（保留了 GPT 式的生成能力）。

这样的妙处：
- **挖小片段** → 偏"理解/完形填空"，训练出 NLU 能力；
- **挖大片段甚至整段** → 偏"长文生成"，训练出生成能力；
- 通过**调节挖空的长度和比例**，一套目标就能在"理解↔生成"之间自由滑动。

> **本质：用"挖空+自回归补全"这一个目标，统一了理解与生成，避免了为不同任务训不同模型。** 这是 GLM 区别于 GPT/BERT 的根本机制，也是它在 Coding（既要读懂上下文、又要生成代码）这类"理解+生成强耦合"任务上有底子的原因。

## 2. DSA 稀疏注意力（解决"长上下文太贵"）

这是 GLM-5/5.1 在效率上的核心改进。**DSA 全称 DeepSeek Sparse Attention（DeepSeek 稀疏注意力）**，由 DeepSeek 在 DeepSeek-V3.2 中提出，GLM-5 是 DeepSeek 之外**首个采用 DSA 的大型模型**。

> ⚠️ 命名修正：DSA 的官方全称是 **DeepSeek Sparse Attention**，并非"Dynamic/Deformable Sparse Attention"。它是一套具体的、有论文支撑的机制（lightning indexer + top-k 选择），而非泛指的"动态稀疏"。

### 2.1 问题根源

标准全连接注意力里，每个 token 要和前面**所有** token 算相关性，计算量随序列长度近似 O(N²)。长文本（20 万字 / 200K token 级）下这部分开销爆炸式增长，是"模型越大、上下文越长、推理越贵"的主因。

> **为什么不能简单用"滑窗/分块/随机"稀疏来省**：这些固定模式的稀疏会**按设计丢信息**——窗口外、块外的 token 永远看不到。GLM-5 报告实测，这类高效注意力即便保留一半层用全注意力，在细粒度检索任务上仍有明显精度缺口（RULER@128K 上最多差 5.69 分、RepoQA@128K 差 7.33 分）。DSA 的卖点正是绕开这个缺口。

### 2.2 机制：lightning indexer 打分 + top-k 选关键 token

DSA 的核心思路一句话：

> **不需要每个词都和所有词对话，只让它和"最重要"的那少数词交流就够了；谁重要，由一个轻量"索引器"先打分、再选 top-k，而且这个"选谁"是模型学出来的、随内容动态变化的。**

具体两阶段（来自 DeepSeek-V3.2 / GLM-5 报告）：

1. **闪电索引器（lightning indexer）**：对每个 query token，用 MLA 压缩后的表示，对前文所有 token 用一套多头 **ReLU 打分公式**廉价地算出"相关度分数"。这一步又快又省（可用 FP8 等低精度），充当主注意力前的"过滤器"。
2. **细粒度 top-k 选择**：只保留分数最高的 k 个 token（DeepSeek-V3.2 中 k=2048），对其余构造稀疏掩码屏蔽掉，主注意力**只在这 k 个 token 上计算**。

这样把注意力复杂度从 O(L²) 降到约 **O(Lk)**（k≪L，近似线性）。

> **为什么 DSA 被称为"lossless（无损）"**：与滑窗/分块不同，DSA 不硬编码稀疏模式——索引器在 token 级别选择，**理论上能触达任意一个相关的历史 token**，没有按设计丢弃长程依赖。GLM-5 报告实证：尽管把 DSA 适配进模型的训练预算远小于 DeepSeek-V3.2（943.7B token），DSA 模型的长上下文表现已逼近原 MLA 模型；用同样 SFT 数据微调后，DSA 与 MLA 在训练 loss 和评测上打平。这正是"成本大幅打下来、长上下文能力一点没丢"的根据。

> **GLM-5 自己的一个工程贡献：确定性 top-k**。DSA 比 MLA 多了一个索引器去检索 top-k，而**这个 top-k 结果对 RL 训练的稳定性至关重要**。SGLang 里基于 CUDA 的 top-k 实现是非确定性的，会让 RL 不稳；GLM 团队改用 `torch.topk` 这类**确定性算子**（稍慢但可复现）来解决。这说明"稀疏注意力"和"Agent RL"两块机制在工程上是相互咬合的。

**效果**：官方口径是把长序列的注意力计算量降到原来的约 **1/1.5 ~ 1/2**（即降 1.5~2 倍），配合 MLA 把 KV 压缩进隐空间，使 200K 上下文窗口的推理成本可控，而理解质量几乎无损。

### 2.3 与 DeepSeek-V4 的对照（帮助理解定位）

| | GLM-5.1 DSA | DeepSeek-V4 CSA+HCA |
|--|-------------|---------------------|
| 思路 | lightning indexer 打分 + top-k 选关键 token（承袭 V3.2 DSA） | CSA(压缩+稀疏选 top-1024) ⊗ HCA(128×压缩 dense) 逐层交错 |
| 共性 | 都是"按需精算"，不为全局付 O(N²) | 同 |
| 风格 | 单一动态稀疏机制，简洁；对**所有层**应用（无损） | 双注意力交错，分工更细，冲到 1M 上下文 |
| 渊源 | DSA 源自 DeepSeek-V3.2，GLM-5 首个外部采用者 | DeepSeek 自家后续演进 |

两家都收敛到了同一个判断：**长上下文里大部分注意力是浪费的，关键是把算力花在真正相关的 token 上。**

> 注：GLM 系列后续的 GLM-5.2 在 DSA 上又加了 **IndexShare**——每 4 层 transformer 共享一个轻量索引器（只在 4 层的第一层算 top-k，索引复用给后 3 层），在 1M 上下文下把每 token FLOPs 再降约 2.9×。这是为了解决"上下文拉到百万级时，连索引器本身都变贵"的新瓶颈。

## 3. MoE 架构（稀疏激活，大而不贵）

### 3.1 基本机制

GLM-5.1 是 **约 754B 总参、约 40B 激活的 MoE**：前馈层拆成很多"专家"子网络，每个 token 只激活其中一小部分专家，于是"总参数很大、单 token 实际计算量小"，兼顾容量与成本。这与 DeepSeek 等主流稀疏大模型同构。

> 同系列的 GLM-5 技术报告披露其 MoE 配置为约 **256 个专家、每 token 激活 8 个**（稀疏率约 5.9%），预训练数据约 **27~28.5T token**，并配合从 DeepSeek-V2 借来的 **MLA（Multi-head Latent Attention）**把 KV 压进隐空间省显存，以及 **MTP（Multi-Token Prediction，多 token 预测）**——用 3 个额外预测层做投机式生成，平均每步接受长度约 2.76 token，相当于把单次前向的产出速度提到约 3 倍。GLM-5.1 延续这一架构路线。
>
> ⚠️ 待核实：以上专家数/激活专家数/MTP 接受长度为 **GLM-5** 报告数字，GLM-5.1 官方未单独披露是否完全一致；按"5.1 是 5 的工程迭代"推断应高度一致，但具体配置以官方为准。

### 3.2 工程亮点：昇腾上的 Layer 级 MoE 绝对均衡

MoE 的老问题是**负载不均**——专家被路由得忽多忽少，导致硬件利用率低、出现计算热点。GLM-5.1 与华为云/昇腾深度协同，在昇腾算力上实现了 **Layer 级 MoE 绝对均衡**：

> 在每一层，让 token 在专家间的分配做到（接近）绝对均匀，从而吃满每张卡的算力、消除热点等待。

配合系统级优化，整体**推理吞吐提升约 30%**。这是"算法均衡"和"硬件适配"协同优化的典型——不只是算法层面追求均衡，而是和具体芯片的并行方式绑定调优。

## 4. 异步 Agent 强化学习（slime 框架，解决"训练与实战脱节"）

这是 GLM-5.1 能做到"千轮工具调用、8 小时自主"的关键，也是它从"会补全代码"走向"能干完整软件工程"的核心。

> 澄清：**slime 不是"代号"，而是智谱开源的一个真实 RL post-training 框架**（GitHub: `THUDM/slime`，亦在 `zai-org` 下；文档站 thudm.github.io/slime）。它最早随 GLM-4.5 推出，此后是 GLM-4.5/4.6/4.7/5/5.1/5.2 共用的强化学习基础设施。其设计目标是 **RL Scaling**——把 Megatron（训练）与 SGLang（推理/rollout）拼起来，支持 dense 与 MoE 大模型的大规模 RL。

### 4.1 问题：传统 RL 训不出长程 Agent

要让模型成为能自主跑多步任务的 Agent，得用强化学习在"真实任务交互"中训练。但传统 RL（RLHF）有个效率死结：
- **生成（rollout）和训练（update）是同步耦合的**——必须等模型把一整条多步任务轨迹跑完（可能几十上百步、耗时很长），才能拿这条轨迹去更新参数；
- Agent 任务轨迹又长又慢，于是 **Learner（训练端）在 rollout 生成期间大量空转**，GPU 利用率低、训练效率极差。

### 4.2 机制：把"生成"和"训练"解耦，异步流水

slime 框架的核心思路一句话：

> **把"生成轨迹"和"用轨迹训练"两件事解耦、异步并行——一边不停地用当前模型在环境里跑任务产生轨迹，另一边不停地消费已产生的轨迹更新模型，两者不再互相等待。**

带来的改变（据 slime 文档与 GLM-5 报告）：
- **生成端（Actor）**：多个 Agent 实例持续与环境（代码库、工具、测试）交互，源源不断产出多步轨迹；用 **FP8** 低精度加速生成。
- **训练端（Learner）**：从轨迹缓冲里持续取数据更新参数，用 **BF16** 保证权重更新稳定，不必等某条长轨迹收尾。
- **解耦的 rollout 引擎**：rollout 服务通过标准 HTTP API 暴露，外部 Agent 框架/环境可直接调用，rollout 逻辑与训练进程边界解耦，便于实现多轮交互、工具调用、环境反馈、verifier 分支等自定义逻辑。
- 配合 GLM-5 **新提出的异步 Agent RL 算法**处理"用稍旧模型产生的轨迹来更新新模型"带来的偏差问题（异步必然引入数据新鲜度问题，算法层面要做校正），并叠加 **APRIL（Active Partial Rollouts）**等系统级优化。

> **本质：用"生成/训练解耦 + 异步流水 + 混合精度"把 Agent RL 的算力空转消除掉**，从而能负担起"超长程任务（上千步、数小时）"的强化训练——这正是长程 Coding Agent 能力的来源。GLM-5 在 slime 上把后训练串成一条 RL 流水线：**Reasoning RL → Agentic RL → General RL（外加 on-policy 蒸馏）**，统一在一套训练栈里跑。

### 4.3 "楼梯式优化"的训练路径

GLM-5.1 的能力提升被描述为**楼梯式优化**：不是一次到位，而是通过异步 RL 在真实任务中**一段段台阶式地爬升**——每一轮交互-反馈-更新都把"自主执行步数 / 任务复杂度"往上推一格。

> **判据（官方 Demo 口径）**：能力曲线被描述为"越跑越好（The longer it runs, the better the result）"。代表性案例——8 小时内从零构建完整 Linux 风格桌面环境（含文件浏览器、终端、文本编辑器、系统监控、可玩小游戏），经 **655 轮自主迭代**完成；同期把一个向量数据库吞吐优化到初始版本的 **6.9 倍**（600+ 轮迭代、6000+ 工具调用，达到 21.5k QPS）；在 KernelBench Level 3 上经**千轮工具调用**实现 3.6 倍几何平均加速，远超 torch.compile max-autotune 的 1.49 倍。这些都印证了"用异步 RL 撑起超长程自主"的机制确实落到了能力上。

> ⚠️ 待核实：常被引用的"1700 步连续工具调用"是第三方评测对能力跃升幅度的概括（20 步→1700 步），非官方逐字数据；官方更常用"655 轮 / 千轮 / 6000+ 工具调用"等口径。

## 5. 国产芯片全栈适配（工程落地）

GLM-5.1 在国产芯片上的意义，不只是"能推理"，更在于**训练本身就跑在国产卡上**——这是它区别于多数"先用英伟达训、再适配国产卡推"模型的关键。

> **训练侧（最重要的事实）**：据报道，GLM-5.1 全程在约 **10 万块华为昇腾 910B 芯片**、基于 **MindSpore** 框架训练完成，**未使用英伟达 GPU**，被称为**全球首个完全基于国产芯片训练的 700B+ 级别模型**。
>
> ⚠️ 待核实：上述"10 万块 910B / MindSpore / 全程不用英伟达"主要见于中文媒体与昇腾生态稿件，智谱官方与 GLM-5 技术报告对训练硬件的逐项口径披露有限，规模数字宜按"报道"看待，待官方技术报告确认。

**推理侧**：发布即完成与多款国产芯片的全栈适配——**华为昇腾、摩尔线程、海光、寒武纪、昆仑芯、沐曦、燧原**。其中：
- **昇腾**：在华为云"Day0"上线，做到 Layer 级 MoE 绝对均衡 + 系统级优化吞吐 +30%（见 §3.2）；以昇腾 Atlas 为例，标准注意力与 MLP 用 **W8A8（INT8 权重+激活）**、MoE 专家用 **W4A8（INT4 权重 + INT8 激活）**量化，使 754B 级模型可部署到单台 Atlas 800T A3。
- 摩尔线程等也同期完成适配。

意义在于：**算法优化（MoE 均衡、稀疏注意力、低比特量化）与国产硬件的并行/调度方式绑定调优**，让超大模型能在非英伟达生态上**既训得动、又跑得快**。

> **为什么"训练用国产卡"比"推理用国产卡"难得多**：推理只需前向、对数值精度和通信容忍度高；训练要反向传播、需要稳定的大规模分布式通信与混合精度，对芯片/框架/集群的成熟度要求高一个量级。能在 910B 集群上把 700B+ MoE 训出来，本身就是国产软硬件栈成熟度的强信号。

## 6. 一页总结

```
四个矛盾 → 四套机制
   │
   ├── 理解 vs 生成：自回归填空（挖span + 自回归补全，一套目标统一NLU与生成）
   │
   ├── 大 vs 贵：MoE(约754B总参/40B激活稀疏) + DSA(lightning indexer打分+top-k选关键token，无损，降1.5~2倍算力，200K长上下文不掉)
   │
   ├── 训练 vs 实战：异步Agent RL「slime框架」(生成/训练解耦异步流水 + 混合精度 → 支撑超长程任务训练)
   │                  → 楼梯式优化 → 千轮工具调用 / 8小时自主
   │
   └── 算法 vs 硬件：国产芯片全栈适配(昇腾910B训练 + 推理Layer级MoE绝对均衡，吞吐+30%)
```

**一句话**：GLM-5.1 不是靠堆参数，而是靠 **"填空式统一理解与生成 + DSA稀疏注意力压成本 + 异步RL练长程自主 + 算法绑国产硬件调优"** 四套机制，把一个开源模型做成了能在复杂工程里自主干长任务、且能在国产卡上训练与推理的 Coding Agent。
